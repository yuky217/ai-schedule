# JUST（应用名；工作目录名仍是 `ai-schedule`）

> **应用名 2026-10-10 起叫 JUST**（`app.json` 的 `name` + `android/app/src/main/res/values/strings.xml`
> 的 `app_name`，两处要一起改）。**`slug`、`package`、`scheme`（`aischedule://`）和数据库名都没动** ——
> 动 `package` 会让手机把它当成另一个应用（覆盖安装变成装第二份、数据全丢），
> 动数据库名等于清库，动 `scheme` 会让悬浮球和通知里的深链全部失效。
> 备份文件**名**改成了 `just-<时间戳>.json`，但文件里的 `BACKUP_FORMAT` 标记仍是
> `ai-schedule-backup` —— 改了它，改名之前导出的备份就再也认不出来。

> AI 辅助的个人日程与任务系统。**第一目的：① 省事；② 做完事。**
> 本文档只讲"工程怎么落地"。产品层面的定论以《项目主文档》为准。

## 一、技术栈

| 项 | 选择 | 说明 |
|---|---|---|
| 框架 | Expo SDK 57 + React Native 0.86 | 跨平台，一套代码出双端 |
| 语言 | TypeScript（`strict: true`） | 领域层零 `any`，类型即文档 |
| 路由 | `expo-router`（文件式路由） | `src/app/` 下的目录结构就是路由表 |
| 本地库 | `expo-sqlite`（异步 API） | 纯本地优先，离线完全可用；web 端走 wa-sqlite（OPFS） |
| 状态 | `zustand` + `AsyncStorage` 持久化 | 设置持久化、数据状态集中 |
| 时间 | `date-fns`（中文 locale） | —— |
| 手势/动画 | `react-native-gesture-handler` + `react-native-reanimated` | Expo Go 内置。**禁止手写 `PanResponder`**（与滚动/点击/翻页互抢，必踩坑） |
| 单测 | `vitest` | 只覆盖 `domain/`（纯逻辑、零 RN 依赖），node 环境运行，不装 jest-expo |

## 二、快速开始

**换机器 / 重装后先跑一次环境脚本**，它把下面那些"只存在于开发者脑子里的前置条件"
变成一条命令（npm 缓存与 Expo 状态目录放在**项目同级**，自动适配任何盘符）：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/setup.ps1
```

它做四件事：建 `<项目同级>/.npm-cache` 与 `.expo-home`、检查 Node、缺 `.env` 就补上
（`EXPO_NO_METRO_LAZY=1`）、然后 `npm ci`，最后打印**每个新 shell 都要设的那几个环境变量**。
加 `-SkipInstall` 可以只做环境不装依赖。

```bash
cd ai-schedule
npm install
npm start          # 扫码用 Expo Go 打开
npm run android    # 或 npm run ios / npm run web
```

类型检查、单测与打包自检：

```bash
npm run typecheck   # tsc --noEmit
npm test            # vitest run —— domain 纯逻辑层
npm run test:watch

# 打包自检：产物输出到**项目外**的临时目录
npx expo export --platform android --output-dir ../_verify/android
npx expo export --platform web     --output-dir ../_verify/web
```

> **改完 `domain/` 必须先跑 `npm test`**，再跑 `typecheck`。
> 纯逻辑层的用例是唯一能挡住"口径悄悄变味"的东西。

> **产物目录不要建在项目内，也不要在项目内建校验目录。**
> 目录里的文件数一旦超过安全删除的批量阈值（50），`expo export` 写盘前清空输出目录的动作会被拦下，
> 表现为"导出莫名失败"。每次用一个**全新**的输出目录最省事。

### 装成独立 App

**两条路，本地已跑通**（2026-10-08 首次成功出包 82M debug APK）。

#### A. 本地出包（当前走这条）

⚠️ **前提：项目必须放在纯 ASCII 路径下。** 这条不是洁癖，是硬约束 ——
`D:\艾粤希\...` 这种中文路径会在三个地方连环炸：

| 阶段 | 报错 | 原因 |
|---|---|---|
| Gradle 配置 | `Your project path contains non-ASCII characters` | Gradle 自检；`android.overridePathCheck=true` 可过 |
| prefab 生成脚本 | `'cli.AppKt' 不是内部或外部命令` | 生成的 `.bat` 含中文缓存路径，bat 按 **GBK** 读 UTF-8 → 命令被拆断 |
| C++ 编译 | `cannot open file 'D:/<乱码>/...'` | ninja 传 UTF-8 路径给 clang，clang 按 GBK 读 → 找不到源文件 |

⭐ **junction 救不了**（实测证伪）：给项目挂 `D:\ais` 指过去，Gradle 仍把路径
**解析回真实路径**，报错里依旧是中文。只能真的把项目放在 ASCII 路径。

当前约定：**项目主目录 `D:\dev\ai-schedule`**（源码 + 构建都在这）。

```bash
cd /d/dev/ai-schedule/android && bash ../run.sh apk
# 或从项目根：bash run.sh apk（内部已带全套 env）
```

`run.sh apk` 里的环境变量**缺一不可**，逐条理由：
- `PATH=/d/node:$PATH` —— PATH 里的 node 是 22.22.2，跑 prebuild 会 **0xC0000409 崩溃**，必须 24；
- `GRADLE_USER_HOME=D:/gradle-home`、`TMP/TEMP=D:/tmp-build` —— 避开中文用户目录（见上表第 2 行）；
- `ANDROID_HOME=D:/Android/Sdk`、`JAVA_HOME=D:/java_JDK` ——
  ⚠️ `which java` 拿到的是 Oracle javapath shim，`dirname` 会得到错目录，**直接写死 D:/java_JDK**。

其他两个坑：
- 🔴 **`echo "x" >> gradle.properties` 是危险动作**：原文件末尾若没换行，新行会**粘到上一行**
  （`...watchedDirectories=[]android.overridePathCheck=true`）→ Expo 拿垃圾值执行 node →
  报 `Process 'command 'node'' finished with non-zero exit value 1`，**报错完全不提属性和换行**。
  改这类文件用 node 脚本并检查末尾换行。
- 🔴 **默认编 4 个 ABI**（`reactNativeArchitectures`）→ 每个都把 C++ 重编一遍，首次要 **1h20m**；
  真机只要 `arm64-v8a`，改成单架构后降到 **15 分钟**。

### 本机踩过的坑

项目根 `.env` 已固化 `EXPO_NO_METRO_LAZY=1` 与 `EXPO_NO_TELEMETRY=1`（Expo CLI 启动时自动读取，**勿删**）。
注意 `npm_config_cache`、`HOME`/`USERPROFILE` 必须在 shell 层设置（npm 与 CLI 早期启动就要用，
`.env` 加载前已读取）；遇到第 1、2 条报错时按提示手动带上。

1. **`npm install` 报 `[safe-delete] 操作失败` / `EPERM`**
   本机的回收站机制会拦截 npm 的清理动作。指定一个普通目录当缓存即可：
   ```bash
   npm_config_cache="D:/艾粤希/.npm-cache" npm install
   ```
2. **Expo CLI 报 `EPERM ... .expo\state.json`**
   CLI 往用户目录写遥测文件被拦。把 HOME 指到可写位置：
   ```bash
   HOME="D:/艾粤希/.expo-home" USERPROFILE="D:\\艾粤希\\.expo-home" \
     EXPO_NO_TELEMETRY=1 npx expo start
   ```
3. **npm 装的包随机报 `MODULE_NOT_FOUND`（缺 `.js` / 缺 `.d.ts`）**
   本机病根（2026-10-07 抓到实锤）：安装时写某些文件的动作会被系统删除守卫拦截，
   文件被改名成 **`原名.DELETE.<hash>`** 挂在原地 —— `main` 指向的 `index.js`、
   类型声明 `.d.ts` 都这么丢的，坏的位置随机，所以症状五花八门。
   **修法一条命令**：把残留复制回原名即可：
   ```bash
   find <目录> -name "*.DELETE.*" | while IFS= read -r f; do
     cp "$f" "${f%.DELETE.*}"; done
   ```
   `<目录>` 是出事的 `node_modules`（npx 缓存条目、项目 node_modules 都一样）。
   以后任何"包文件莫名缺失"先扫 `.DELETE.*`，别再重装碰运气。
4. **web 打包报 "Unable to resolve module ./wa-sqlite/wa-sqlite.wasm"**
   Metro 默认不把 `.wasm` 当资源解析。已通过根目录 `metro.config.js` 修复：
   `assetExts.push('wasm')` + 开发服务器加 COOP/COEP 响应头
   （`expo-sqlite` 的 web 端依赖 SharedArrayBuffer）。该文件是必须保留的。
5. **web dev 首屏报 "Metro error: Worker chunk not found for: expo-sqlite/web/worker.ts"**
   根因：Metro 默认 lazy bundling（dev 端 web 首次构建的图不含异步模块），
   而 expo-sqlite 的 web worker 恰是异步模块，序列化时断言"必须为 worker 单独出 chunk"失败。
   已通过项目根 `.env` 的 `EXPO_NO_METRO_LAZY=1` 修复（关掉 lazy，worker 进图）。
   静态导出（`expo export`）不走 lazy，不受此问题影响。
6. **`vitest.config.ts` 报 "ESM syntax in a file loaded as CommonJS"**
   配置文件**必须叫 `vitest.config.mts`**。也**不要**给 `package.json` 加 `"type": "module"`——那会搞坏 Expo。
   另外 `@` 别名要在 vitest 的 `resolve.alias` 里**再配一遍**：vitest 不读 tsconfig 的 `paths`。

## 四、主流程 ↔ 代码位置

## 五、几条必须守住的约定

0. **⭐ 用户操作要尽量简单，而且默认他在用手机。** 每加一个交互都要能回答四句：
   **默认值是不是已经对了**（对的默认 = 用户零操作）？**这一步能不能并进上一步**？
   **这件事非得用户决定吗**（能推导的就别问）？**这个动作在手机上做得到吗**？
   为"更灵活"而加开关、加二次确认，都是这条的敌人。
   注意它**不**推翻第 9 条：简单不等于替用户下结论。
   第四句不是空话：课表导入页曾经写着"在课表页 Ctrl+A 全选"——那是桌面上的动作，手机上不存在，
   写出来等于没写。本机只在 web 上跑预览，很容易写出这种文案，所以**预览默认套一层手机尺寸的框**
   （`http://127.0.0.1:8099/phone`），看到的比例才是真机的样子。
1. **界面不直接碰数据库。** 一律走 `repositories`；跨页面的数据联动统一由 `app-store.refresh()` 完成。
2. **软删除。** 删除只写 `deleted_at`，所有查询自动带 `deleted_at IS NULL`。删掉的东西要能同步出去。
3. **同步预留字段。** 每张表都有 `updated_at / deleted_at / remote_id / sync_state`。现在完全当纯本地用，将来升级"本地优先 + 云同步"不用改表、不用迁移。
4. **只涨不落。** 专注界面的"小东西"用 `growth_seconds`，取 `max(历史, 本次)`，暂停、中断、提前结束都不会缩水——不惩罚是这个产品的底线。
5. **AI 默认关闭，且关闭时产品完整可用。** 日历、清单、待办不依赖任何 AI 能力；能力关闭时自动降级到 `domain/routing.ts` 的本地启发式。
6. **脱敏在调用前。** 任何走云端的文本都先过 `capabilities/desensitize.ts`，并把遮蔽数量如实告诉用户。
7. **产品要最简。** 高级功能一律藏在 `settings.advancedEnabled` 之后，默认不开。
8. **排序必须确定性。** 分组/列表排序不能只按数量降序就收工——数量相同时先后会取决于数据读出来的顺序，
   界面行序会莫名跳动。必须补一个固定的次关键字（见 `domain/review.ts` 的 `KIND_ORDER`）。
   **例外：传入顺序本身就是用户意愿的地方不补 id** —— 待办的档内顺序是用户拖出来的
   （`domain/todo.ts` 的 `compareInBucket`），搜索结果里 `updatedAt` 相同的一批同理
   （`domain/search.ts` 的 `byUpdatedAt`）：补 id 会把意愿按字母重排。
   判断标准是**"这个顺序有没有人在表达什么"**，不是"能不能补"。
9. **完成动作只由明确的勾选触发。** 点行/点块 = 进详情，长按 = 拾起
   （**拖了是排序、原地松手是弹菜单**，靠位移区分）。任何"点一下就算做完"的设计都算误触，禁止。
   注意 web 上长按后浏览器仍会补一次 click（原生手势会 cancel 触摸，浏览器不会），
   所以"长按 + 行内本来有点击动作"的地方要用时间戳吞掉紧随其后那一次点击
   （待办 `longPressAt`、日历页同款 —— 2026-10-08 补：日历月/周/日视图的
   拖拽改期曾因漏了这层，拖完松手直接跳进详情页；拖拽**起止都要**记时刻，
   只记开始的话拖久了窗口就过期）。
10. **页面不能因为数据为空就整页 early return。** 空态只能替换内容区，导航（工具栏、翻页）必须一直在
    ——日历就踩过：空月份里连翻页按钮都没了。
11. **同方向的滚动不能直接套。** 竖直 `ScrollView` 里再放一个竖直 `ScrollView`，
    Android 上外层会把手势全吃掉，内层**根本滚不动**（而且在 Web 上常常是好的，
    所以本地测不出来）。内层必须开 `nestedScrollEnabled`；要紧的地方再加一道
    "手指按住内层时把外层 `scrollEnabled` 关掉"的保险（`time-wheel` 的
    `onScrollLockChange` 就是这个）。横向嵌竖直不受影响。
    已经踩过两次：`calendar-day` / `calendar-week`（时间轴）和时/分滚轮。
12. **同一件事只能有一个定义，而且必须有名字。** `time.startAt ?? time.dueAt` 曾经被
    原样抄了 **13 遍**（日历页 5 处、首页、详情页 2 处、周视图、输入框、选择器、重复、
    回顾、预设 3 处、提醒），反向的 `dueAt ?? startAt` 还有 4 处。它**不会报错**，
    所以改一处时没有人会想起另外 12 处 —— 直到某处悄悄漂移，表现成"任务算错天 /
    提醒错时间"，那时已经查不出是哪一处。现在全收在 `domain/task.ts`，三个名字对应
    **三个不同的问题**（不是同一个东西的三种读法）：

    | 函数 | 回答 | 用在哪 |
    |---|---|---|
    | `taskAnchor` | 什么时候**发生**（优先 startAt） | 归到日历哪一天、排序、排提醒、滚重复 |
    | `taskDue` | 什么时候**到期**（优先 dueAt） | 期限显示、紧迫度 |
    | `hasAnyTime` | **落进时间轴了吗**（含 endAt） | 该不该画到日历 / 甘特图上 |

    前两个方向相反、却是**并列的两条事实**（"周三 14:00 开会，但周二前交材料"里，
    开始与截止指向不同的日子）；第三个含 endAt，前两个刻意不含（单独一个结束时间
    不构成"什么时候发生"，但它确实占着时间，仍要画出来）。
    `domain/task-anchor.guard.test.ts` 会**扫源码**守住这条：再手写第 14 处就变红，
    并直接告诉你该换成哪个函数。

13. **加表必须同步挂进三处**：`schema.ts` 的 `TABLES`、`BACKUP_TABLES`（漏了 = 恢复后
    这张表的数据全部蒸发，打卡表漏过一次）、`client.ts` 的 `clearAllTables`
    （子表在前；`import.ts` 的 replace 复用它，别再自己写 DELETE 顺序）。
    `import.test.ts` 有不变量守着第一处。重复任务完成滚期有一条不变量：
    **下一期必须是未来**（`advanceRepeatingTask` 一路滚过已过去的期）——
    用户晚勾一天，只从原锚点 +1 会滚进过去、立刻被判 missed。
    撤销完成（`reopenTask`）必须把提醒排回去：`completeTask` 撤过通知。
    **勾选圈的语义是开关（`toggleTaskDone`，2026-10-08）**：所有列表行的圆圈都走它 ——
    已完成的行再传 `completeTask` 是空操作，等于把"撤销"锁死在详情页里（用户点名修过）。
    详情页常驻底栏同理：已完成时按钮就是「撤销完成」，不要再放第二处"重新打开"链接。
    备份覆盖导入 / 清空数据之后必须处理通知：导入后 `resyncReminders()`、
    清空后 `cancelAllReminders()`，否则旧任务的提醒照弹、新任务的一条没排。

14. **验证分三档，按"改了什么"决定，不按"改了多久"。**

    | 改的东西 | 怎么验 | 为什么是这一档 |
    |---|---|---|
    | 文案、间距、颜色、单页布局 | 浏览器预览（`/phone`） | Web 和真机在这些上几乎一样 |
    | 手势、拖拽、滚动、动画、弹层、键盘、导航跳转 | **Expo Go 真机跑一次** | Web 恰好测不到这些 —— 已经栽过两次 |
    | 通知、权限、精确闹钟、文件、后台、悬浮球 | **打包 APK（dev build）** | Expo Go 里要么没有、要么行为不同 |
    | 动了数据库 schema | **真机一次**（Expo Go 够用） | 迁移只跑一次，而且手机的库和浏览器的库**不是同一份** |
    | 要给别人用 / 换手机用 | **打包 APK** | —— |

    触发时机：**每做完一个"能从头走到尾"的功能就真机一次**（不按天数、不按提交数）；
    攒到要交付时再打包。小改动不要打包 —— 打包一次的成本远高于它当场能给的信息。

    有一句话要当成纪律：**"在 Web 上正常"永远不能当作签字依据**，
    只要这次改动碰了上表第二、三行。浏览器的定位是"看长什么样、点着顺不顺"，
    不是"看能不能用"——这两件事不同，混起来会让人误以为验过了。

15. **临时产物当场清掉，不攒清单。**

    （2026-10-07 曾改成"清理一律延后、攒到收尾统一删"，用户当天否决：还是原来的方式顺手删。
    留这一条只为记姿势，不再是流程。）

    - 只清**我自己生成的临时产物**（导出目录、截图、浏览器 profile）；
      用户数据、项目源码、`_preview-web` 这个**活着的预览目录**永不碰。
    - 删除姿势固定为 `find <dir> -type f -delete` + `find <dir> -depth -type d -delete`
      （`find -delete` 不经过 safe-delete 守卫，一次能清空整棵树；`rm -rf` 在中文路径下必失败）。
    - **不在 C 盘攒**：C 盘余量小，导出产物一律落 D 盘。

16. **视觉是"极致极简工具风"，改动必须服从它而不是装饰它。**（2026-10-08 设计审查定）

    - 色板只有一层：暖灰中性面 + 近黑近白文字（`theme.ts`），**没有彩色强调色** ——
      界面上唯一的重色就是文字本身，主按钮 = 文字色填充。别往里加颜色。
      例外自成体系：`course-colors` 的 8 色课表板、色板里的 `tint`（链接色，≥4.5:1）。
    - 改色必须**对比度实测**：正文 ≥4.5:1（`textSecondary` 压 `backgroundElement` 也要过），
      不许目测。`global.css` 里 html/body 的底色与 `theme.ts` 成对维护，改一边改另一边。
    - 全局文字走 `ThemedText`（它带 `tabular-nums` —— 日程 app 的数字必须等宽，
      否则时间列在列表刷新时抖动）；新文本组件别绕开它。
    - web 字体 Spline Sans 在 `global.css` 加载（display=swap，离线静默回退）；
      原生端一律系统字体。**声明了字体却没人引用 = 白声明**，ThemedText.base 是唯一接线点。
    - 动效克制但必须可降级：web 端 `prefers-reduced-motion` 已在 `global.css` 统一处理。
    - 触达区的取舍要写下来：勾选圈 24px 是**刻意**的（hitSlop 曾造成整行误触，
      见 task-row 注释）—— 44px 标准在这里让位于"明确点这个圈才算完成"。

## 六、数据库

七张业务表 + 一张元信息表：`tasks` / `ideas` / `containers` / `task_chains` / `marks` / `focus_sessions` / `task_checkins` / `app_meta`。

- 嵌套属性（`time`、`progress`、`repeat`、`tags`、`steps`）以 JSON 列存放，领域层看起来仍是嵌套对象，映射细节只在 `data/db/mappers.ts`。
- 索引按真实查询路径建：状态、截止、开始、所属容器，且都带 `deleted_at`。
- **开库顺序是 `PRAGMA → 建表 → 迁移 → 建索引`，写死在 `data/db/bootstrap.ts` 里，不能换。**
  （踩过一次：索引原本跟建表写在同一段 SQL、先于迁移执行。`CREATE TABLE IF NOT EXISTS`
  对老库是空操作，老库的 `tasks` 表里没有新列，于是 `no such column: parent_task_id`，
  整段 `execAsync` 失败 —— **只有"用过一段时间的老库"会中招，全新安装完全正常**。
  所以：**凡是引用"某个迁移才加出来的列"的索引，都只能放 `INDEXES`**。
  回归测试在 `bootstrap.test.ts`，用 Node 自带的 `node:sqlite` 把 v1 / v2 / 全新库各真跑一遍。）
- 开库失败时**不缓存那个失败的 promise**（`client.ts`）：缓存了就等于一次失败绑死整个会话，
  之后每个页面都拿到同一个旧错误，看起来是"到处都无法正常运行"，真因却早飘过去了。
- 升级表结构时递增 `SCHEMA_VERSION`；备份文件里也带这一版号，便于写迁移。
- **当前 `SCHEMA_VERSION = 9`。** 演进：v3 `tasks.parent_task_id`（子任务，只允许一层）
  + `tasks.sort_order`（手工排序，NULL 视为 0）+ `task_checkins`（打卡）；
  v4 `courses` + `terms`（课表）；v5 `events`（考试等固定日程）；
  v6 `courses.changes_json`（单次调课）；v7 `ideas.breakdown_task_id`（想法拆解）；
  v8 `tasks.location`（地点，与课程 / 固定日程上的同名字段对齐）；
  v9 `tasks.all_day`（全天，2026-10-10）。
  **加列一律带默认值或可空**，于是老数据不用回填、读出来跟以前完全一致。
- **全天必须单独存一列**（v9），不能靠"start_at 是 00:00"去推：
  用户完全可以真的把一件事定在零点，那样真·零点日程会被错认成全天。
  全天仍然写 `start_at/end_at = 当天 00:00 / 23:59:59` —— **锚点不能省**，
  省了它就会从所有按时间取数的列表里消失（与"有属性没锚点"同一个坑）。
  显示层有四处要说"全天"而不是假时刻：行、详情页时间文案、**日视图顶部横幅**
  （时间轴从 `START_HOUR=5` 起，全天的 00:00 会落到负坐标＝画在可视区外）、
  **小组件/首页的"下一个截止"**（⭐ 要拿 `endAt` 比，用 `startAt` 比永远比不过现在，
  一条"今天全天"的事会凭空消失）—— 口径收在 `domain/task.pendingUntil`。
- **跨天拖拽用「长按拿起 + 手动激活拖拽」的组合手势**，不是 `Pan.activateAfterLongPress`：
  **`Pan` 没有 `maxDistance`（只有 `LongPress` 有）**，所以按住期间手指抖动超过触摸阈值
  长按就前功尽弃 —— 表现为"有时拖得起来、有时拖不起来"，抬阈值治不了根。
  现为 `Simultaneous(LongPress(minDuration=300, maxDistance=24), Pan(manualActivation))`：
  长按只负责拿起（容忍 24pt 抖动），Pan 等 `pickedUp` 为 1 才跟手（否则跟页面滚动抢）。
  **点击仍归行内 `Pressable`**，所以"点开详情 / 勾完成"零回归，也避免"点勾选圈顺手打开详情"。
- 列表查询一律带 `parent_task_id IS NULL`（仓储里的 `TOP_LEVEL` 常量）；
  排序一律 `ORDER BY COALESCE(sort_order,0) ASC, created_at DESC`（新任务在最上面）。

### 子任务 / 打卡的语义边界（别混）

- **子任务** → 父任务完成态**自动推导**（全完成 = 完成，取消一个 = 打回待办）。
- **打卡** → **不**改任务状态。习惯的"做完"是"今天做了"，明天还得出现；
  "今天做没做"看打卡表，"这件事还做不做"看 `task.status`。
- **一次一条 + 连续创建**（`app-store.addSubtasks` / `addTasksToContainer`，2026-10-10 改）：
  输入框**整段就是一条**；点「加」或按软键盘的「完成」建一条，**建完清空并把焦点还给输入框**，
  可以一条接一条地敲（Things / Todoist 的 quick-add 循环），手不用离开键盘。
  任务详情页的子项、项目页的新建任务都用它。
  - **不再按换行切**（2026-10-10 撤掉 `domain/subtask-lines.splitSubtaskLines`）：
    换行只是排版，不是"这是另一件事"的声明 —— 自动炸开是替用户猜边界，切错了还得一条条删。
    子项应该是用户一条条主动放上去的**积木块**（对齐滴答清单的手动归档心智）。
  - 代价是"贴一整段清单"变慢了，所以靠**连续创建**补回来：慢的不是操作次数，
    是"要不要重新点一下输入框"。输入框因此改单行 —— 让「完成」键等于"建一条"。
  - 批量接口**只 refresh 一次**：一条条刷会看到列表一条条蹦出来，像是卡了。

### 详情页的输入框：**输入即存**（2026-10-10）

标题 / 备注 / 地点 / 等待 / 目标这几个框以前只在**失焦（onBlur）**时写库：
手点一下别处确实会存，但**直接返回**（手势返回、安卓返回键、点 Tab 走）压根不触发失焦，
那一屏字就这么没了 —— 而备注恰恰是"想到什么赶紧记一句"的地方，丢一次就再也想不起来。

现在打字停下 600ms 自己写一次；失焦、以及**离开页面**时立刻补一次
（`flushPending` 把五个都存一遍，不是只存刚动过的那个 —— 用户可能在标题框改了字、
又在备注框改了字，然后直接返回）。

### 想法怎么变成能动手的事（`domain/idea-breakdown.ts`）

想法库原本是条**死路**：只能归档，没有任何办法变成"要做的"。拆解就是那条出口，
产出固定是**一条父任务 + N 条子任务**，不是 N 条并列的任务：

- 步骤离开那件事就没有意义（"查资料"是谁在查？），散进待办只会把它搅成一锅粥；
- 挂在父任务下还白拿一条规则 —— **子任务全部完成时父任务自动完成**，
  那正是"这件事做完了"的定义。

口径全在纯函数 `planBreakdown` 里（有单测）：标题取**第一个非空行**并截到 40 字
（想法常是"一句标题 + 一段展开"，整段进标题会让待办里出现一条糊成一团的巨长行），
**截掉的部分进 `note`** —— 截断是为了好看，不是为了省地方；步骤去空、按原顺序去重、上限 20。
父任务**刻意不给时间**：拆出来的是"要做哪些事"的清单，不是排期；没时间 = 待规划，
它会自动落到待办 —— 那正是拆解产物该去的地方。给每一步自动派时间等于替用户排了一遍程。

指针存在想法这一侧（`ideas.breakdown_task_id`，schema v7）：想法是**来源**，
它只需要知道"我说出去的话有没有人接"，不需要反过来遍历谁引用过它。
**步数不存** —— 步数是子任务表的实时事实，存一份就会跟实际对不上
（用户去任务详情页删掉一步，那个数字就开始骗人），所以想法行上是现算的。

拆过之后**不再让拆第二次**：点那一行直接去看那条任务，追加步骤走任务详情页
**已有的**子任务能力。同一件事开两条路，迟早出现"从这边加的和从那边加的对不上"。

### 回顾：只报做到了什么（`domain/review.ts`）

「回」这一环的立场既写在文件头也写在这里：**只报做到了什么，不盘点没做到什么。**
逾期只作为一个中性数字出现，没有红色警告 —— 回顾的作用是让人愿意继续做下去，
变成绩效面谈的话用户第二次就不会点进来了。

- 五个区间：**今天（日报）/ 本周 / 本月 / 近 7 天 / 近 30 天**。默认仍停在「本周」——
  默认值该回答的是"我最近怎么样"，那才是进来时的真问题。
- **「今天」就是日报**：日粒度在别处没有落脚点（首页只说"下一步做什么"，
  日历只说"几点有安排"），而它恰恰是最常被问的那句"我今天到底做成了什么"。
  只有一天时 `describeRange` 只说那一天 —— "共 1 天"是废话。
- 三条不变的口径：完成率的分母是**本期该做的**而不是全部积压（拿积压当分母，
  完成率永远 3%，那不是反馈是羞辱）；本期完成数按 `completedAt` 算、可以打穿本期边界
  （提前做完是功劳）；连续天数是全局概念，不被区间截断。

### 频率型任务的"本期"（`domain/habit-period.ts`）

"每周跑 3 次"这类任务的目标达成，是唯一需要推导状态的地方，口径全部收在这一个文件：

- **本期 = 把时间轴按间隔切成等长的块，含此刻的那一块。** 三个单位共用这一个公式：
  daily 以 1970-01-01 起算、weekly 以 1970-01-05（周一）起算、monthly 以 1970 年 1 月起算。
  所以块边界永远落在周一 / 每月 1 号，"本周""本月"符合直觉；`interval > 1` 是按边界并块，
  不是滚动窗口。
- **"本期做了几次"不存，从打卡记录现算**（`occurrencesInPeriod`，按天去重）。
  以前 `task.progress.occurrencesThisPeriod` 存了这个计数，但**没有任何地方负责归零**，
  还被三处代码各自 +1（打卡、重复任务滚动、专注）撞成三种意思 —— 结果"每周 3 次"
  一旦达标就**永远停在已完成**，下一周做完也不会回来。**原则：存事实，不存会漂移的计数。**
- **完成态是推导出来的，不是推送出来的**：`state.refresh()` 之前跑一次
  `reconcileFrequencyTasks()`，用 `desiredFrequencyStatus` 把频率型任务收敛到正确状态
  —— 本期够数则完成，不够数却停在完成态则打回待办。同一个规则同时管住
  "新的一周它自己回来"和"撤销打卡后打回待办"。
- 因为状态是推导的，**对频率型来说"勾完成"没有意义**：
  `completeTask` 对它等同于"今天打卡"，列表行的圆圈走的也是这条路。

### 任务 → 打卡的转换（`domain/habit-convert.ts`）

任务是**终点型**（勾了就结束），打卡是**过程型**（每天重置）。所以"转成打卡"不是换显示方式，
而是**换判定域**：从 `task.status` 换到打卡记录。转换动的字段是固定的那几项
（类型、完成判定、重复规则、次数目标，状态回到待办），**刻意不动 `time`** ——
用户可能真想"每天早上 7 点跑步"。若任务原本已完成过，默认补一条今天的打卡
（`seedCheckin`），否则那次记录会因为一次转换凭空消失。转换会抹掉什么
（时长目标、原重复规则）由 `warnings` 如实报出，界面先呈现再执行。

### 日历数据是"按可见范围查"的

日历**不**从全局 store 拿全部任务：个人日程攒上几年就是几千条，而屏幕上永远只有一个月。
窗口算法在 `domain/calendar-window.ts`，查询走 `taskRepository.listScheduledBetween`
（判据是**时间窗重叠**，用 `COALESCE(start_at, due_at)` / `COALESCE(due_at, start_at)` 两端夹，
不是比单一锚点——只比 `start_at` 会漏掉"上个月开始、下周截止"的任务）。
页面自己 load，并以 store 的 **`dataVersion`**（每次 `refresh` 自增）作为失效信号。

### 专注启动：固定指针的横向选择器（`components/focus-picker.tsx`）

首页那张专注卡不是"一个提案 + 换一件按钮"，而是一个**指针固定、内容左右滑动**的选择器
（借 iOS 时间轮的思路）：**选中由位置决定，不由颜色决定** —— 手指不用瞄准，
停在哪一格哪一格就是答案。格子顺序固定：

```
[ 写一件新的事 ]  [ 你刚挑的那件? ]  [ 今天的 ≤5 件 ]  [ ＋ 从全部里挑 ]
```

- **候选只取 `today`，不掺"还没排时间"的那些**，最多 5 条。那是"还没安排"的池子，
  铺进滑动区就等于让用户在轮盘里做筛选——那是「＋」那一格的活（它弹 `ChoiceSheet`）。
- **滑到「＋」上自动弹出清单**：用户滑到那儿的意思本来就是"这儿没有，给我看全部"，
  再让他点一下是多余的。
- **默认停在哪一格由 `domain/focus-candidate.defaultFocusIndex` 决定**：
  ① 此刻正落在某件安排里 → ② 标了「进行中」的 → ③ 都不成立就落到「写一件新的事」。
  刻意**不**做成"永远指向第一件待办"——默认项必须能解释自己，随便挑一件解释不了。
- 归位时机：`onScrollEndDrag` 里不能直接归位（动量还没跑完，会停在半路），
  至少要等到惯性结束；没有惯性时用一个短兜底计时器。这条主要是为了 Web
  （react-native-web 的 `snapToInterval` 不总生效）。
- **整张卡只有一个按钮**：以前是「开始」+「先干着，结束再命名」两个键。
  但"不命名就开干"已经被第一格（写一件新的事 + 标题留空）表达了 ——
  同一件事说两遍，还逼用户按之前先判断一次"该按哪个"。现在按什么由指针停在哪格决定：
  停在任务上 = 开始专注、停在新事上且填了名字 = 记下并开始、停在新事上且空着 = 先干着、
  停在「＋」上 = 弹全部清单。**挑这一行也刻意压得比开始键小**：主角是"开始"，不是"挑"。
- **首页只有两块**（2026-10-07 删）：专注启动卡 + 一行折叠（纪念日 / 习惯）。
  删掉了「今天」列表 —— 那几件已经全在滑动区里，再列一遍是同一件事说两遍，
  还把首页撑成一份家当清单；完整列表的家是日历。
  删掉了「待规划」「在推进」两张卡 —— 待办、项目各有自己的 Tab，一次点击就到，
  首页替它们做的只有"提醒你还存在"，那不配占首页的位置。
- **专注那张卡没有背景框**（`Card` 的 `bare`，2026-10-10）：它是页面的重心，不是"又一张卡"。
  上面下面那些有框的都是"顺便看一眼"的东西，靠**材质**把两类分开 ——
  否则页面上排着的就变成一串同样重的方块，重心反而没了。

### 专注怎么变成日历上的一条

专注是本项目里**唯一知道"这件事我实际花了多久"的地方**，日历记的是"什么时候"，
两者合起来才是一条完整记录。规则在 `domain/focus-link.ts`：

- `focusSpan(startedAt, actualSeconds, now)` 把一次专注翻译成起止时刻。**不到一分钟不落**
  （手滑点开又退出不该留垃圾），**结束时间不超过"现在"**（会话可能被挂了一夜才收尾）。
- **只给"还没安排过时间"的任务补时段**（`shouldStampFocusSpan`）：已经排进日历的任务
  有它自己的时间，专注只提供"投入了多少"，不重新安排用户的日程。
- 结束时**没绑定任务** → 新建一条任务并落到日历：起了名字用名字，没起名就叫「专注」
  （2026-10-08 用户拍板：未命名的也进日历，统计和日历不该是两个口径）。
  这段时间**已经发生过**，所以它是一条"做过什么"的日志、直接记成已完成；
  这与"不许替用户把已有的待办标完成"并不冲突——我们**新建**了一条记录，
  没有改动用户已有的任何决定。
- 「这段就算把它做完」开关**始终默认关**：干了多久、和这件事算不算做完，
  是两件事 —— 勾不勾由用户当场决定。

### 完成、以及"已经过去"：日历上的两类淡出

日历回答的是"这段时间发生过什么"，不是"还剩什么没做"，所以**已完成的照样画出来**
（这也是 `listScheduledBetween` 刻意**不过滤** `status != done` 的原因——
以前"取不到"就是从那一句开始的）。好坏由 `domain/task-state.ts` 一份口径决定，
返回 `done / overdue / missed / active / upcoming / unscheduled` 之一。

**两类"过了时间"必须分开**，混在一起必做错：

| 类型 | 例子 | 过了时间算什么 | 界面 |
|---|---|---|---|
| 截止型 `deadline` | 作业、报告 | **`overdue` = 欠着** | 不淡出，还标出"已过期 N 天" |
| 固定型 `fixed` | 开会、上课 | **`missed` = 那段已经过去了** | 淡出（opacity 0.72） |

已完成的淡到 0.5 + 标题划线 + 左侧色条转灰，并且**不挂拖拽手势**
（月视图连抓手都不渲染）——那天已经过去了，挪它没有意义，要改就进详情页。
日视图里完成项也不再显示勾选圈：**改状态只发生在详情页这一处**。

两条硬规则：**时间过了绝不自动完成**（状态只由用户的明确动作改变）；
「过期 / 已经过去 / 已错过」的口径**只有一个** —— `domain/task-state.ts`
（它区分 `overdue`=欠着 与 `missed`=已错过），不要另写一个"时间比现在早"的判断。

### 时间怎么选：预设 + 常驻调整栏（`time-wheel` + `date-time-picker`）

`SCHEDULE_PRESETS` 覆盖高频（今天上午 / 今晚 / 明天前…），点一下就是一整步。
预设兜不住的（"下周三 19:20"）走**详情页时间卡里那张常驻的调整栏**：属性（日程/截止）
→ 日期（自建 `month-picker`，不引第三方日历库）→ 时/分双滚轮（分钟步进 1 分钟，"会议 14:07 开始"
不能被 5 分钟粒度挡在门外）→ 「设为 …」一键落库。

**这里刻意没有"自定义…"这一层入口**（2026-10-07 用户点名去掉）：要精确调时刻的场景本来就该
直接看到滚轮，多包一层只会多按一下。推论：`ScheduleSheet` 的职责只剩"预设 + 提醒 / 重复"，
`SheetView` 里的 `custom` 层已删。栏是常驻的，所以草稿必须**在页面加载时就落在任务现有时间上**
（没有时间就给"今天 09:00"这个能直接确认的默认值），并且**任何改时间的动作都要顺手同步草稿**
（点预设、挪过期事件同理）——否则预设把时间定到"明天 14:00"之后，接着按一下确认就把它顶掉了。

**记一件事界面同理**（2026-10-07 用户点名合并）：以前输入框下面单挂一张"什么时候"预设卡，
说的和「时间」chip 是同一件事，卡片已删；三个预设（今天 18:00 / 明天 09:00 / 明天 18:00 截止）
挪进时间面板顶部（`DateTimeSheet` 的 `presets`），**点一下即应用并收起** —— 预设的值是完整的，
没必要再按确认。不点就是不定时间，长按 chip 清空。
顺带修掉一个真 bug：`capture.tsx` 以前用 `activePreset.build()` 覆盖 `options.time`，
默认那个"不定时间"会把用户刚在 chip 里设的时间**清成 null**，现在直接透传 `options.time`。

`DateTimeSheet.onConfirm` 因此改成**带值回调** `(value) => void`：预设要在同一次点击里
"应用 + 确认"，若走 state 再读会是旧值（异步 setState）。

滚轮是**手写控件**，它踩过的三个坑都写在 `time-wheel.tsx` 文件头，改之前先读：
① 竖直套竖直滚不动（见约定第 11 条）；② 挂载时没滚到当前值 —— 用 `useRef(初值)`
当"别回滚"的判据，首次挂载就会命中 early return，于是不管草稿是 09:00 还是 19:37，
轮子初始都停在 `00`；③ 没滚过半格时不吸附，拖一点点松手会停在两个刻度之间
（吸回去时的容差 `> 1px` 是必须的，否则 scrollTo → onScroll → 吸附会死循环）。

栏内嵌在详情页的滚动区里，所以**滚轮按住期间要把整页滚动关掉** —— 详情页为此持有
`wheelLocked` 并把它喂给 `Screen` 的 `scrollEnabled`（同约定第 11 条，外层会吃掉滚轮手势）。

为什么不装 `@react-native-community/datetimepicker`：它是原生控件，**Web 端不支持**，
而这个项目的 web 端必须能用。也正因为这个门槛，时间选择器这个位置**没有合格的现成库** ——
所以这一处是"把交互做简单"，而不是"手写系统级控件"。

### 语义词片：用「哪天」排期（`buildSemanticTime`）

待办里**长按一行、原地松手**，弹出一层「今天 / 明天 / 周末 / 下周 / 稍后」。
消化待办时的第一念是"今天做还是周末做"，不是"14:00 开始"；选中即落库，
这条随即出现在日历上（而且从「还没排时间」升到了「今天」那一档）。

与预设的分工别混：**预设指定钟点**（今天上午 = 09:00），**词片只指定哪一天**。
两种任务分开处理：

- **已经有时间**的：只换日期，**时刻和属性都不动**（"明天 09:00 的会"挪到周末还是 09:00）；
- **还没时间**的（还在「还没排时间」那一档）：落到那天 **23:59 作为截止** —— 用户说的是"今天做"，
  不是"今天 9 点开始"。用 9 点这个数，下午点一下立刻变成"已经过点"，看着像出错。

边界一律取**未来的那一天**：周日点「周末」给下周六（不给刚过去的昨天），周一那天点「下周」
给下周一（不给今天）。落回过去等于把任务弄丢在日历背面 —— 四条边界都有单测盯着。
「稍后」是例外中的例外：它只描述时刻（现在 + 两小时），与哪天无关。

长按因此有了两种去向，靠**位移**区分（`reorderable-list.tsx`，阈值 8px，手指按住的自然抖动
只有一两像素）：动了 = 排序，没动 = 弹菜单。不传 `onLongPressIdle` 的列表保持原样。

### 过去的事得有个出口（`domain/past-event.ts`）

淡出只是"看起来不吵"，不解决"它还在那儿"——上周三的会一直挂着，用户每次翻到那天
都要重新想一遍"这个我到底办没办"。而铁律是时间过了绝不自动完成，所以这个决定只能用户来下。
详情页在 `missed`（且只有固定型）时给一张卡，三个出口，都是一步到位、没有新概念：

| 出口 | 意图 | 做什么 |
|---|---|---|
| **挪到〈今天/明天〉14:00** | 忘了，但还要做 | 换日期、**保留原时刻与时长**（14:00–15:00 整体平移） |
| **改成待办** | 会不开了，事还得做 | 撤掉四个时间字段 + 类型改执行型 → 回待办 |
| **就这样吧** | 不做了 | 软删除（按两下）；**不标成完成**，不进完成率、不进回顾页 |

两条别写错的地方：

- **「挪到哪天」由 domain 算，不是固定"今天"**：用户晚上 20:37 才来处理"昨天下午的会"，
  挪到今天 14:00 就是四小时前 —— 卡片不会消失，用户会以为按钮坏了。
  规则是**挪到下一个还没到的那个时刻**：原时刻今天还没到就今天，已经过了就明天。
- **只给固定型**。截止型过期是"欠着"，欠着的东西不该被劝着放弃 ——
  那一类在界面上要显眼，不是要淡出，更不该给"就这样吧"。

## 七、备份与恢复

- **导出**：`exportBackup()` → 写入 `document/backups/`，再唤起系统分享面板。用户可以存网盘或发给自己。
- **导入**：`restoreFromPicker('replace')` → 选文件、校验格式、整库事务内覆盖写入；失败整体回滚。
- 备份存的是**数据库原始行**，目标是原样恢复，不是给人看的漂亮 JSON。

## 八、当前状态与后续路线

**主流程「记 → 分 → 落 → 行 → 完 → 回」已全链路打通。**

- **记 / 分 / 落**：一句话记录（`capture-input`），自动识别时间（`parse-schedule`，纯本地启发式），
  按两档分流落到想法库 / 待办 / 日历；**提醒不自动开**（见下）。
  **想法态下那四个快捷设置一个都不出现**（2026-10-10）：勾了「这是灵感」或整条就是
  想法页那格（`ideaOnly`）时，时间 / 清单 / 重复 / 提醒**整排隐藏** ——
  想法不排期、不催办、也不归清单。摆着它们只会让人以为"灵感也得定个时间"，
  点了才发现用不上，于是怀疑是自己哪儿没弄对。既然这一格只有一种归属，界面就只给一种可能。
  **提醒的规则（2026-10-08 用户拍板）**：`reminderMinutesBefore` 三态 ——
  **`null` = 不提醒（默认）**、`0` = 准点、`>0` = 提前 N 分钟（与课表同一个字段名同一套含义）。
  以前 `null` 当准点用，于是"没点过提醒那一格"的人也照样被通知，而 chip 显示成灰的「提醒」——
  界面说没设、行为上却设了。会响的只有两种情形：**文字里提到了提醒**
  （`parse-schedule` 认「提醒 / 叫我 / 喊我」，**动词是入场券** ——
  "提前半小时出发"是行程不是提醒），或者**用户自己点过那格**。**手动的压过识别的**
  （点过「不提醒」也压过文字里写的）。只提了提醒、没写提前多久 →
  按事情的样子给默认值（`domain/reminder.defaultReminderMinutes`），**按顺序判、命中即止**：
  ① 截止 60（要留出做的时间）→ ② 重复与习惯 0（到点就该做）→
  ③ **标题里有准备动作 60**（"19:00 出发去机场"：收拾、出门、赶车都要时间）→
  ④ **有地点 20**（要走路、换教室、找楼，10 分钟只够站起来）→ ⑤ 其余 10。
  ③④ 的依据都是**算出来的、不用用户填**：地点是结构化字段（已填/已识别），
  准备动作只认「出发 / 出门 / 收拾行李 / 赶飞机(车、高铁) / 接人送人」——
  **词表窄是刻意的**：「开会」「上课」「交材料」都不算（它们回答"这件事是什么"，
  不是"要不要提前收拾"），放宽了"课程设计答辩"的「课」、「会议纪要」的「会」
  都会被误抬到 1 小时，而**猜错的提醒用户不知道去哪儿改**（与 `extractLocation` 同一取舍）。
  「赶」必须带交通工具（"赶紧"不算）、「接」必须带人（"接电话"不算）。
  顺序两处是刻意的：② 压 ④（"每天 8 点吃药"不会因为有地点变成提前 20）、
  ③ 压 ④（有地点只到 20，但"出发去机场"要 1 小时）。
  ⭐ **课表与任务同源**（2026-10-08 用户拍板"统一口径"）：课的默认值原本硬写 15、
  任务那套兜底 10，同一件事从两个入口看是两个数。现在 `DEFAULT_COURSE_REMINDER`
  **委托同一个 `defaultReminderMinutes`**，并且课天然有教室 → 落到
  **「有地点的日程」那一档（20 分钟）**。这才是"统一"的实质：不是把 15 改成 10，
  而是让课归到它本来该在的那一档（课 = 要动身去教室，与「地点：三教101」的会同数）。
  ⚠️ 只作用于**新建**的课；已存库的不迁移 —— 用户可能自己调过（哪怕就是 15），
  替他改是僭越，而且"默认 15"与"手动 15"在库里长得一样，无法区分。
  ⚠️ 同时修掉一个潜伏 bug：`createCourse` 的 `reminderMinutesBefore` 必须用
  **`=== undefined`** 判断而不是 `??` —— `null` 在这个字段上是**有含义的值**（不提醒），
  `??` 会把"我要关掉提醒"静默改回默认值。`undefined` 才是"没提这件事"。
  收口在 `resolveReminderMinutes` —— **chip 上显示的值就是最终存进库的值**，
  所以 location / 原文两条依据在 chip 与落库两处都必须传（有测试盯着）。
  **「12点前交」也是截止**（2026-10-08 补）：此前截止式要求必须带日期词，
  于是"光一个时刻 + 前"被"只有时刻"接走、落成"固定时间 12:00"——
  在日历上变成一个**要出席的事件**，而它其实是个截止（提醒该提前 1 小时、过了该进"已过期"）。
  **粘一整段通知也认**（2026-10-08 补）：**时间照旧识别，标题只取它真正的那一行**。
  三百字的活动通知粘进来 → 标题「团委大会暨团委素质拓展活动开展」+ 10月14日 19:00–21:50，
  地点进 `location` 字段、服装要求这类原文进备注。
  依据是个很朴素的约定：**这段文字的第一行就是它的名字**（通知、公告都这么写），
  所以只做"跳过寒暄与分节小标题、洗掉序号与 emoji、剥掉『关于…通知』的壳"，
  **不做语义理解**（那是能力层 `Understand` 的事）—— 一行都挑不出像样的就退回整段，宁长不猜。
  **地点是一等字段**（schema v8，2026-10-08 用户拍板）：课程与固定日程一直有 `location`，
  只有任务没有，于是"地点：xxx"只能躺在备注里、日历上看不见"要去哪"。
  识别**只认写明标签的那种**（`地点 / 地址 / 场地 / 位置` + 冒号，见 `extractLocation`）——
  不认「在体育馆开会」：「在」字在中文里太常见（"在家工作"是地点还是状态？），
  认错地点比认不出糟得多，用户会按着错的地方出门。
  值的边界收在**不含句读、也不含下一个标签**上（"地点：三教101，请提前到"只取到"三教101"）；
  **「写了等于没写」的值不认**（"待定 / 另行通知"），宁可那行原样留在备注里；
  **引号只在首尾成对时剥**（`"人民大会堂"` → 人民大会堂），
  「"一站式"学生社区211」这种强调引号原样留着（剥了会剩个孤零零的闭引号）。
  两条保护：**地点与时间片段重叠时整个作废**（"地点：明天10点楼下集合"里裹着时刻，
  切掉会把时间一起带走 —— 时间比地点要紧）；**标签前不吃空格**（时间正则会把尾随空格
  圈进自己的区间，地点从那个空格起算就会"碰"上，被 overlap 检查误杀）。
  地点落在三处：详情页一行可编辑、日历块上与时刻同行（块矮时不显示）、**提醒通知的正文里**
  （看到通知那一刻正是要决定往哪走的时候）。
  两个配套口径：**时间已经在字段里了，备注里不再留一份残渣**（"时间： （下周三） 晚"整行抹掉，
  但"时间：另行通知"那种没被抠过的行一个字都不许动）；**想法库相反**——那里的 `content`
  就是**用户输入的原文**，不走提炼：想法不排时间、也没有地点字段，抠掉任何一个字都是白丢信息。
  **时刻的小时位认中文数字**（2026-10-08 补）："下午五点"= 17:00，此前只认阿拉伯数字、
  "下午五点理线"会安静地落成"明天 23:59 截止"。配套的闸：**「周X点」不读成时刻**
  （`execTime` 跳过前一字是 周/期/礼/拜 的中文数字命中），"周五点外卖"照旧是周五截止。
  **记录页只有一行输入框 + 一排 chip**（时间 / 清单 / 重复 / 提醒，2026-10-07 减负）：
  「时间」那一格同时承担手动值与识别结果 —— 有手动值显示手动值、没有就显示识别到的，
  点它改、长按清；原来那行只读的"识别到…"提示已删（它和「时间」按钮说的是同一件事）。
  **记完不换页**（2026-10-08 用户点名撤掉整页结果卡）：换成 `capture-success` 的大勾动效，
  1.6 秒自动关页、点一下立即关、原生上加成功触觉。通则：**只为说一声"成了"的界面，
  反馈必须自己退场**（动效 / snackbar / 触觉），不能变成一道新的确认工序；
  需要用户读、选、确认的内容才配占一页。
- **待办**（Tab 名与页面名，2026-10-10 由「收集箱」改名）—— 一个**五档完整列表**
  （已过期 → 今天 → 往后 → 还没排时间 → 已完成，与 `domain/todo.ts` 同一份口径），
  档可折叠、默认全展开；**只有「还没排时间」那一档能手动拖动排序**
  （别的档是按时间排的，拖了会弹回去，见下"排序打架"）。点条目进详情页；
  长按拖动排序，**长按原地松手**弹语义词片（今天 / 明天 / 周末 / 下周 / 稍后）一步排期，
  排完自动落日历并重排提醒。

      （`failOffsetX` 14 < pager 的 `activeOffsetX` 16）。跟手期间锁页面滚动（`scrollEnabled`）。
    - 清单**进页面滚动流**，不做成固定高度的抽屉 —— 不必为它再嵌一层滚动容器
      （嵌套滚动是这项目踩过的坑：滚动锁、超时兜底、web 上还不一样）。
      收起时容器高度为 0、`pointerEvents` 关掉，但**内容仍挂载**（要靠 `onLayout` 量高度）。
    - **每天最多 3 件事**（`MONTH_PLAN_TASK_LIMIT`）：某天真排了 8 件事时全列出来会吃掉半屏，
      整月的疏密被一条长尾压平，而"哪天最重"圆点已经说过了；超出走「还有 N 件 · 看这天」进日视图。
      **只有课的那天也算有安排**，但课**合并成一行**（一天四门课不占四行、也不给勾选）。
      只收**属于这个月的日子**：月历画的是 6×7 整张网格（带着上/下月几天），
      照抄整张网格的话 9月29号会在 9 月和 10 月两张清单里各出现一次。
    - 清单里的任务行**不给拖拽抓手**（它是拿来"看"的，改期在月历上有另一条路）；
      勾选、完成灰掉、点进详情全部复用 `TaskRow`。
  - **待办面板**（`components/inbox-panel.tsx`，2026-10-10）：**日历页上唯一的待办入口**。
    以前同一份数据有两个入口 —— 月视图底部那条（拖拽源头，只在月视图）和右侧抽屉
    （任何视图都能拉，但盖住月历于是拖不到格子上），用户眼里就是"两个待办列表"，
    而且各有各的残缺。现在合成一个底部磁吸浮层，两处的好处都留下：
    - **任何视图都能拉出**，且**它本身就是拖拽源头**（不再限于月视图）；
    - 三档磁吸点：**peek**（只有把手「待办 · N 件」，不占版面）→
      **expanded**（列出待规划，每行可拖到日历格子上）→
      **full**（从展开态再往上拉过阈值 → 跳待办页）；
    - ⭐ **拖某行时面板自动缩回 peek**（`collapseWhen`）：否则它压在月历上方，
      手指够不到日期格，这一拖永远落不下去 —— 这正是旧抽屉"拉出后拖不到日历"的根因；
    - ⭐ **手势只挂在把手上**：每行都带着自己的长按拖拽手势，外层再挂一个按下即激活的
      普通 Pan 会把它们全抢走（行就再也拖不起来）。把手是唯一没有别交互的地方；
    - 内容**始终挂载**（收起时只裁掉 + 不吃触摸），不挂载就量不到高度；
    - ⚠️ **它只列两档，不是"待办的第二个家"**（2026-10-10）：面板存在的理由是
      **"往日历上排期"**，所以只放需要你动手落位的（已过期 + 还没排时间）。
      今天 / 往后已经在日历上躺着了，再列一遍是重复；已完成更不用。
      完整五档只有待办页一处（点把手再拉一下就是它）。
  - **「加到这天」**（月视图选中日那张卡底部，2026-10-10）：记下来的就直接属于这天，
    月历上立刻有点。以前只能绕到别处去记（记完不带时间的落进待办，
    **在月历上根本不出现**，于是"我明明记了，日历却没反应"）。
    时间怎么定：文字里写了时刻就留那个时刻、只把日子换到这天；没写就落到这天 23:59 作为
    截止 —— 与待办拖到日期格是同一份口径（`buildTimeOnDay`），不在这里另写一个数。
    输入框**常驻**：走到这一步的人已经决定了"这天要加一件"，再让他点一次只是多一次操作。
- ⭐ **待办页与日历的关系**（2026-10-10 定型，`(tabs)/inbox.tsx` + `domain/todo.ts`）：
  用户的原话是"想找个地方看到所有待办，不管设没设时间；**开会、上课这种不算待办**"。
  这句话翻译成数据基本只有一条判断：**待办 = 执行型 + 习惯型**（`TaskKind`）。
  所以它**不需要用户手工归档、也不需要"标记为待办"的开关** —— 类型本身就把事答了
  （与"不做智能清单"那条立场一致：落位规则只有一套）。日程型（开会/上课）天然排除，
  想法型留在想法库等拆解。
  - **名字**：Tab 名 / 面板把手 / 路由标签统一叫「待办」（2026-10-10 由「收集箱」改名）。
    改成五档完整列表之后，Inbox（GTD 里指"收进来还没分类的"）这个名就跟内容对不上了。
    ⚠️ **只改用户看得见的词，不动代码里的 `inbox` 路径**（`app/(tabs)/inbox.tsx`、
    `InboxPanel`、悬浮球深链 `aischedule://capture`）—— 改路径要动路由表，收益为零。
  - **为什么把日历里那一栏删掉**：那一栏与待办页是**同一份口径的同一份数据**，
    只是画在日历里。用户眼里就是"两个待办"（跟当初"两个收集箱"一模一样的病）。
    删掉之后日历剩四栏，待办页成为唯一的"跟时间无关的事"的家；
    日历页要快速摸到它们走底部磁吸面板（已过期 + 还没排时间）。
  - 分档五档固定：**已过期 → 今天 → 往后 → 还没排时间 → 已完成**，空档整块不出现
    （空标题会让人以为"是不是没加载出来"）。分档顺序不做成用户可选项。
  - "已过期"只收**截止型**（欠着的）；日程型的过期不算欠债（`taskDisplayState` 已分好这两种含义，
    这里直接复用，不重新解释一遍时间）。**已完成的档按"最近做完的在前"**、最多 10 条。
  - ⭐ **只有「还没排时间」那一档给拖拽排序**（`ReorderableList` 的 `reorderable` 开关，
    2026-10-10）：别的档是按时间排出来的（`compareInBucket`），手拖写进 `sort_order` 也不会生效 ——
    松手那一刻行会被重新排序弹回原位，看起来就是"拖了没用"。与其给个假动作，不如关掉。
    但**跟手浮层、拖到日期条、原地松手弹词片三路照旧**：这三件事与"排序"无关。
  - 档内排序**不补 id 做次关键字**：稳定排序返回 0 就能保留传入顺序，
    而"传入顺序"在这里有意义（用户自己拖出来的意愿），补 id 会把意愿按字母重排。
  - ⭐ **`isTodo` 有一个例外**（2026-10-10 可达性扫描扫出来的真洞）：
    **日程型但完全没排时间，也算待办**。原来"只看类型"的话，
    一条 `schedule × 没时间` 的任务会从**四个列表同时消失** ——
    日历不要它（没时间）、待办页不要它（不是执行/习惯型）、
    日历里那一栏不要它（已删）、项目列表只收挂进容器的。用户记了件事，然后就再也找不到它了。
  - 它**不走时间窗查库**（用的是 store 里全量 `tasks`，因为"没排时间的待办"本就不在任何时间窗里），
    也没有翻页箭头、横滑手势整个关掉 —— 翻到"上个月的待办"没有意义。
  - **分档口径只有这一份**：待办页列五档、日历磁吸面板只取其中两档，
    两处都调 `groupTodos`，不各写一个"哪些算欠着"的判断。
- ⭐ **全库搜索**（`app/search.tsx` + `domain/search.ts`，2026-10-10）：
  入口是**首页右上角最左边那颗放大镜**（`(tabs)/index.tsx` 的 `headerActions`，
  现在是「搜索 · 回顾 · 设置」三颗）。
  放在首页而不是做个 Tab：搜索是**偶发动作**，占一个常驻位就是拿五分之一个底栏换一个
  "偶尔用一次"的东西（与"不做智能清单"同一取舍）。
  - **一次搜五类**：任务 / 清单（容器）/ 课 / 纪念日 / 想法，**组序固定**
    （任务 → 清单 → 课 → 纪念日 → 想法）、**空组不显示**（搜"英语"时没有课的组就不出现标题）。
  - 匹配是**大小写不敏感的子串**（`toLowerCase().includes`），**纯本地、不联网**；
    多条命中**按 `updatedAt` 倒序**（最近碰过的靠前），不补 id 做次关键字（见约定 8 的例外说明）。
  - 搜的内容：任务的标题/备注/地点，课的课名/老师/地点，想法正文**与标签**，纪念日的名字。
  - **想法页的检索是另一回事**：那是"在想法库这一格里找"，输入框的 `q` 由搜索页带过去
    预填（`useLocalSearchParams`），落在同一个页面上继续筛。
  - ⚠️ **别把"语义检索"当卖点**：`AiCapability.SemanticSearch` 这个能力
    **代码里一行调用都没写**（只改过 placeholder 文案）。所以它的 `description` 已改成
    "（尚未实现）"，想法页那张"到设置里打开语义检索"的提示卡也删了 ——
    **界面不许拿一个没接线的开关承诺任何事**。
- **课表**（`components/timetable-view.tsx` + `timetable-grid.tsx`，日历的第四栏）：
  「学期设置」（开学日 + 作息表）是它的底座，课只存**节次**，几点到几点由作息表算出来。
  默认作息排到**第 12 节（第 9 节起算晚课）**；"课间不止一种"靠**逐节改时刻**解决——
  点表里任一节的开始/结束单独挪，剩下的照旧。
  - **导入只有一条路：先拿到"带星期的表格"，再交给 `course-text` 解析。** 拿表格有两种：
    ① **内嵌浏览器抓**（`app/import-browser.tsx` + `entry/scrape-timetable.ts`）——在 App 里
       登录教务，脚本按**屏幕横坐标**把课程格对齐到「星期X」表头（认位置，不认 HTML 结构），
       同源 iframe 也支持，产出的制表符文本回喂同一个解析器；
    ② **粘贴**——但从教务页复制的文字里**星期列整个丢了**（7 列压成一串、空格什么都不剩），
       所以粘贴进来必须逐条点星期。不是解析器偷懒，是信息真没了
       （真数据夹具 `domain/__fixtures__/jwgl-grid.txt` + 12 条测试守着这条结论）。
  - **一格多行用 `U+2028` 连**：抓取时若让格内换行原样进文本，整张表会散成一堆单格行、
    列全部错位。所以格内换行一律换成 `U+2028`，`course-text` 按它拆回多行、展示时合成 ` / `。
  - **可以只导一部分**：点过星期的时段跟着进，没点的这次不带；整门课的时段全没点 →
    整门先不导（不导成"没有上课时间"的空壳）。导入是**整体替换**现有课表。
  - **点课块 = 打开这一块自己的面板**（`components/course-slot-sheet.tsx`）：
    改到别的日子/节次、这一次不上、撤销这次调整，另有一个出口通向整门课。
    不是"点一下直接进课程详情"——**单次调课必须知道是哪一次**（哪一天的那一块），
    而课程详情是整门课的视角、没有日期，在那儿做不了这件事。
  - ⭐ **单次调课 / 停课**（`domain/course.ts` 的 `CourseChange`，schema v6 的 `changes_json`）：
    session 管**整学期**（"每周三 3-4 节"），change 只管**某一天的那一次** —— 作用域不同，
    所以后者塞不进前者（塞进去就等于"这门课这学期只有这一天有课"）。
    - 身份 = **原定日期 + 原定那一段**（`dateKey` + `fromKey`）两个一起。只按日期定位的话，
      同一天有两段（周一 1-2 节 + 周一 5-6 节）会把另一段一起改掉。
      两个 kind（moved / canceled）**共用同一套身份**，所以"先调到周四、又改成不上"
      是同一条记录换状态，不会两条同时生效。
    - `coursesOnDate` 两步走：本来该在这天的被调走/停掉的跳过，被调来的补进来。
      **停课那一格默认不返回**（提醒、首页"下一节课"、日历背景带问的都是"要上什么"），
      只有课表格子传 `includeCanceled: true` —— 那一格要是凭空消失，用户既确认不了
      "取消生效了没有"，也**没有地方点回去恢复**。停课的块画成灰掉+划掉标题。
    - **被调整过的块不给拖**：拖拽在这个网格里的含义是"整学期换时间"，
      而单次调过来的那块不属于整学期 —— 硬拖会因为按 `sessionKey` 找不到原安排而
      **毫无反应**（`moveSession` 返回 null），所以干脆关掉，改它去面板里改。
    - 撤销就是删掉那条 change（`dropCourseChange`）；停课时的「恢复上课」走的是同一个动作。
    - 已知取舍：原安排**后来被删掉**时，"调过来的那一次"仍然照常画出来
      （用户亲手排的一次课不静默丢掉），它变成一条只能从课表撤销的孤儿调整。
  - **长按拖动课块换星期/节次**（跨度跟着走，周次与教室不动）。
    拖拽期间关掉网格横向滚动——横滑看后面几天和横拖换天是同一个方向，两个都要必然打架。
    课程详情里**点某一段 = 改它**（星期/节次/周次都能改，右侧 ⊖ 才是删）——
    网格拖拽改不了**周次**，只有这里能。改周次的面板要**预填原值**（`weeksToText`）：
    空着的话默认整学期，用户只改节次、一按保存，"1-16周(单)"就悄悄变成整学期，
    而界面上两个数字都对，看不出来。所以 `weeksToText` 的输出**必须**能被 `parseWeeks`
    原样读回去（course-text 的测试守着这条回路）。
  - 可以在**设置 → 基础 → 课表**里整个关掉：关掉后日历里没有「课」这一栏，
    日/周视图也不再画上课时段（`settings.timetableEnabled`，默认开）。

- ⭐ **简约模式**（`settings.simpleMode`，默认**关**，2026-10-10）：一个开关关掉界面上

  用熟之后它们只剩噪音，而且它们一多，界面就在跟人说话，而不是让人看内容。

  - 默认关：第一次来的人还不知道那些圆点是什么意思，这时候图例有用。

  任务条可长按拖拽改期（整天平移、保留时分）；容器条不给拖——它是框架，拖它就该连成员一起推，那是另一件事。
- **行**：首页的**专注启动选择器**（固定指针 + 左右滑，默认格子由 `defaultFocusIndex` 决定）
  → `app/focus.tsx` 计时（可暂停，离开即结束）。小东西随专注时长生长（只涨不落），
  时长按 `domain/focus-link.ts` 分流回任务；**勾选型任务只累计时长、不自动完成**（不替用户下结论）。
  结束时有两条出路：绑了任务 → 累加进度并（若它还没安排过时间）把这段时段落进日历；
  没绑任务但填了名字 → 直接生成一条已完成的记录进日历。
- **完**：勾选完成；子任务自动推导父任务；习惯打卡独立计数。
  **完成 ≠ 消失**：已完成的事仍留在日历上，只是灰掉、划掉、拖不动（`domain/task-state.ts`）。
- **回**：`app/review.tsx`。区间切换（本周 / 本月 / 近 7 天 / 近 30 天）→ 小结 → 三个大数字 →
  专注趋势（自绘柱状图，不引图表库）→ 完成情况（按类型 / 按清单）→ 习惯热力图。
  立场：**只报做到了什么，不盘点没做到什么**。
- **其他**：习惯打卡页、纪念日、子任务、备份导出 / 恢复、AI 能力层契约（默认全关）。

### 悬浮球（Android 独立版专属）

入口层的第一个"系统级"入口：一颗小球浮在所有应用之上，点一下直接落到记录页。
**Expo Go 和网页端都看不到它** —— 它是原生模块，只有打出来的 Android 版才有。

- **原生模块在 `modules/overlay/`**（在 `src/` 之外），JS 门面是 `src/entry/overlay.ts`。
  没装第三方悬浮窗库：两条候选都堵着 —— 一条用**普通后台服务**
  （Android 8 之后 App 一退后台气泡就被系统回收，那样"悬浮窗"根本不成立），
  另一条的 gradle 依赖是 `com.facebook.react:react-native`，而那个制品在 Maven 上
  **只发到 `0.71`**（新坐标是 `react-android`，已到 0.87），跟本项目的 0.86 并排放会撞类。
  这里只需要五个方法，自己写反而更短、更可控。
- **必须是前台服务**：`FOREGROUND_SERVICE_SPECIAL_USE` + `foregroundServiceType="specialUse"`
  + 一条常驻通知。那条通知顺势当"这东西怎么关"的入口，不算纯负担。
- **气泡不渲染 React Native**：它是 `WindowManager` 上一个圆形 View，拿应用图标当脸。
  点它 = 走 `aischedule://capture` 深链落到记录页。**不把记录页复刻进悬浮窗** ——
  复刻一份就等于给"记录"另开一个入口，那正是本项目一直在避免的事。
- **拖拽 / 贴边**：过一个小门槛才算"拖"，否则手指抖动会把"点一下"判成"拖一下"；
  松手吸到最近的边，不让球停在屏幕中间挡内容。位置写在**窗口参数**的 `x/y` 上
  （气泡坐标 = 窗口坐标 - 投影留白），不是改内部 View 的 margin。
- ⚠️ **窗口尺寸 = 气泡 + 一圈投影，绝不能是 MATCH_PARENT**（2026-10-10 真机踩到）：
  曾经用一个铺满屏幕的透明容器托着气泡（改 margin 就能拖，写起来省事），
  结果**整个屏幕的触摸都进了这个窗口** —— 气泡之外没有任何 View 消费它们，事件就地丢弃，
  传不到下面的应用。表现就是"开了球之后，除了球哪儿都点不了"。
  `FLAG_NOT_TOUCH_MODAL` 只让"窗口区域之外"的触摸穿透，窗口铺满屏就等于没有外面。
- **连点保护**：点球到记录页真的打开之间有一瞬空白，没反馈时用户会再点一次 →
  开出两个记录页。所以按下先缩一下（有反馈），并给 `openCapture()` 加 600ms 节流。
- **`attachBubble()` 挂不上就返回 `START_NOT_STICKY`**：权限被撤时空转会被 STICKY
  反复拉起来，白耗电，还会让 `isShowing()` 一直说"浮着"。挂上了才要 STICKY。
- **降级不报错**：`requireOptionalNativeModule('Overlay')` 拿不到就返回 null，能力层如实报
  `unavailable` 并给一句人话说明，**不抛异常** —— 网页端渲染设置页时每次都走这条路。
- **意愿与状态分开记**：`settings-store.overlayEnabled` 记的是**用户想不想要**（所以重启后
  会自己回来，不用再点一遍）；`getOverlaySupport()` 每次读**原生侧真实值**（权限给没给、
  服务在不在跑）。从授权页回来靠监听 `AppState` 接着把球开起来，不用用户点第二次。
- ⚠️ **这段代码还没编译过、没在任何真机上跑过**（Android SDK **2026-10-08 已装到 `D:\Android\Sdk`**，
  只剩跑 prebuild + gradle；此前"本机没有 SDK"的说法已过期）。它属于
  "必须打包 dev build"那一档 —— 见第五节约定 14。首次打包时最可能出问题的地方依次是：
  前台服务类型声明、`startForeground` 的 API 34 分支、深链是否被正确解析。

- **考试提醒（2026-10-08）**：固定日程**没有提前量字段**，什么时候响由
  `domain/event-reminder.ts` 定死：**考前一天 20:00**；万一这条排不上（比如晚上十点才导入明天的
  考试）退到**开考前 1 小时**；两个时刻都过了就不排。理由是考试该什么时候提醒有明确答案，
