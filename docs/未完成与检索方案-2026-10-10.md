## 1. 收集箱 = 完整分档列表

### 1.1 口径：复用，不新写

直接走 `domain/todo.ts` 的 `groupTodos(tasks)` —— 五档固定（已过期 → 今天 → 往后 → 还没排时间 → 已完成）、档内按时间排、空档不显示。

为什么必须是这一份：上一轮刚刚踩过一次「两个收集箱分工不同」——**同一件事两套口径，最后一定会出现"这边说它过期了、那边排在后天"**。而且 `todo.ts` 已经有 22 个测试，`TodoView` 也已经在用它渲染。

`isTodo` 基本只看类型（执行型 + 习惯型）——**日程型不进**。这是已拍口径（开会、上课不是"欠着你的"），收集箱跟着走。
⚠️ **一个例外**（实施中补的，见 §4.1）：**日程型但完全没排时间，也算待办** —— 否则它会从四个列表同时消失。

### 1.2 界面

- 五档标题行**可点，折叠 / 展开**。**默认全展开**：对的默认值 = 用户零操作。
- 「已完成」档用 `TODO_DONE_LIMIT = 10`，末尾接一行「还有 N 件 · 去回顾页看全部」（`TodoView` 已有这套写法）。
- 收集箱页底部那块「已完成 N 件」折叠区**删掉** —— 它和上面新增的「已完成」档是同一件事，留着就是两个入口。
  `app-store` 的 `recentlyDone` 字段只被这一处消费（已 grep 确认），一并撤掉。

### 1.3 拖拽：只有「还没排时间」档能**排序**，但每一档都能**拖到日期条**

这是全案唯一需要想清楚的地方。

收集箱现在的顺序是**用户亲手拖出来的意愿**（落 `sort_order`）。而分档列表里，「已过期 / 今天 / 往后」三档的排序口径是**按时间**（`compareInBucket`）。两套口径挂在同一个长按手势上，结果是**用户拖了、松手、位置弹回原处** —— 这比干脆不给拖更糟。

所以分开处理：

| 档 | 拖动排序 | 拖到日期条 / 日历格 | 原地松手出语义词片 |
|---|---|---|---|
| 还没排时间 | ✅ 写 `sort_order` | ✅ 定到某天 | ✅ |
| 已过期 / 今天 / 往后 | ❌ 不落库 | ✅ **改期 = 顺延** | ✅ |
| 已完成 | ❌ | ❌ | ❌ |

⭐ 第二列几乎不用写新代码：`buildTimeOnDay` 里早就写了"已经有时间 → 保留时刻与属性，只换日期"（内部走 `buildRescheduledTime`），日历页的 `handleDrop` 用的也是它，注释原话就是"已经有时间的换日期（时刻不动）"。

于是**把一条过期的截止拖到未来的格子 = 顺延**，语义已经是对的：10/8 23:59 拖到 10/10 → 10/10 23:59。零新增 domain 代码，而且是用户自己下的决定 —— 正好落在「只呈现不改数据」这条定案上。

实现上给 `ReorderableList` 加一个 `reorderable?: boolean`（默认 `true`）：false 时不写顺序、不回调 `onReorder`，但"拖出去"和"词片"两路照旧。

### 1.4 磁吸面板（日历页浮层）

按定案：**只列「已过期」+「还没排时间」两档**，其余档收成一行「还有 N 件 · 去收集箱」。

- `INBOX_DRAG_LIMIT = 4` 保留：有界才不会在月历上糊掉半个屏。
- `collapseWhen={draggingTask !== null}` **不动** —— 拖起来自动缩回把手，是"能拖到格子"成立的前提（旧抽屉拖不到日历的根因就是它压着月历）。
- 「已过期」排在前：它是"最该先安排"的那一档。
- ⚠️ **删掉日历第五栏之后，这个面板从"方便"变成了"必需"**：日历页剩下的月 / 周 / 日 / 课四栏全都是"有时间才进得去"，那么**"还没有时间的事"在日历页唯一的落点就是这个面板**。所以面板上「还没排时间」这一档**不能省**。

## 1.5 删掉日历第五栏「待办」

第五栏那个视图**就是**收集箱要变成的东西。留着它 = 同一份数据两处渲染，而且两处**手感不一样**（收集箱的行可拖，待办栏的行不可拖）—— 同一个列表两种行为是最难向用户解释的一种不一致。

顺带解决的历史问题：待办栏当初放进日历页的理由写得很清楚（`TodoView` 注释：「不想让它自己占一个 Tab」）。现在收集箱**本来就是它自己的 Tab**，这条理由不成立了。

**不用改的东西**：`domain/todo.ts` 一行都不动 —— `groupTodos` / `BUCKET_ORDER` / `TODO_DONE_LIMIT` 全部照旧，只是消费者从 `TodoView` 换成收集箱页。`components/todo-view.tsx` 只有一个消费者（已 grep 确认），它的渲染部分直接搬进收集箱页、加上拖拽即可，这个文件随之消失。

**顺手能清掉的特判**：日历页里 `mode === 'todo'` 共 **15 处**，其中三处是"待办是唯一没有翻页箭头的视图"（`561` / `593` / `970`）以及 `headerLabel` 里那句"手上欠着的 · N 件"、`legend` 的空字符串分支。删掉整栏之后这些分支全部回归统一。

**代价（可接受）**：在日历页看月历看到某天，想立刻跳到"我欠着什么"，要改成点一下底部 Tab。Tab 就 5 个、一键直达；而且月历下拉清单（`month-plan`）已经把"这个月每天都有什么"留在页内了。

### ⚠️ 一个名字上的不一致，请你知道但先别动

删掉第五栏之后，**界面上再也不会出现"待办"这个词**（Tab 叫「收集箱」）。而内容变成了"已过期 / 今天 / 往后 / 还没排时间 / 已完成"——**"收集箱"（Inbox）在 GTD 里指的是"收进来还没分类的"，现在它装的是一整套分档**，名字和内容对不上。

建议本轮**不改名**（"收集箱"已经出现在 README、拖拽文案、悬浮球深链等一堆地方，改名要牵动 Tab 顺序与文案，该另开一轮）。真要改，我倾向把 Tab 名从「收集箱」改成「待办」——让界面和 `domain/todo.ts` 用同一个词。等你一句话。

## 2. 日历上标识「未完成」

**现状**：只有日视图有（截止型过期 = ⚠ 图标 + 「已过期 3 天」，见 `calendar-day.tsx`）。周视图、月历圆点、月历下拉清单**都不标** —— 过期和没过期长得一模一样。

按定案「圆点分深浅」：

- **未完成的任务点 = `theme.text`（深）**；已完成 / 已过去的 = `theme.textSecondary`（浅，即现状）。
- 课与考试不动（空心 / 方块）—— 它们的形状语义已经占满，不再加码。

要动 `domain/calendar-shape.ts`（这一处是"日历形状语言的唯一定义处"）：

1. `DayMarks` 加 `openTasks?: number`（那天未完成的任务数）。
2. `dayShapes` 的返回从 `CalendarShape[]` 变成 `DayDot[]`，`DayDot = { kind: CalendarShape; open?: boolean }`（`open` 只对 task 有值）。
3. **新增一条名额规则**：同为任务点时，**未完成的优先保留**。和"任务 > 考试 > 课"是同一条精神 —— 欠着的更该被看见。

⚠️ 一个已知的小损失：**选中那天看不出深浅**（选中的日期圈是实心深色，圆点统一退回 `theme.background`）。可以接受 —— 那天已经被高亮，而且它的清单就摊在下面。

周视图建议跟同一套 tint（`calendar-week.tsx` 已有同样的 `taskDisplayState` 判断），成本很低。

> 🚧 **周视图这条本轮没做**（只改了月历圆点）：`calendar-week.tsx` 未改动。
> 周视图里任务块本来就是实心块 + 勾选圈，未完成/已完成已经能靠"圈勾没勾"看出来，
> 深浅属于锦上添花，不是缺口。留着，想做时是一处 tint 的事。

## 3. 全库搜索

**现状**：全库搜索**没有界面**。全项目唯一的检索是想法页那个关键词框，而且是 `content.includes()` 纯子串匹配。

- 新建 `domain/search.ts`：`searchAll(query, { tasks, containers, courses, marks, ideas })` → 分组结果。**纯函数、可测、不查库** —— 五份数据本来就都在 store 里（`app-store` 的 `tasks` / `containers` / `courses` / `marks` / `ideas`）。
- 新建 `src/app/search.tsx`。
- **入口 = 首页右上角加一颗放大镜**（实施后这一排是「搜索 · 回顾 · 设置」三颗，放大镜在最左）。首页是回得最频的地方，"我现在想起来要找什么"也总是从那儿开始。
- 分组：任务 / 项目 / 课程 / 纪念日 / 想法。组内按 `updatedAt` 倒序（最近动过的先），空组不显示。
- 跳转：任务 → `/task/[id]`，项目 → `/container/[id]`，课程 → `/course/[id]`，纪念日 → `/marks`，想法 → `/ideas?q=…`（那一页已有搜索框，预填关键词即可）。

### ⚠️ 顺带必须处理的一条：想法页那句是空头支票

现在想法页写着"到设置里打开「语义检索」，就能用一句话把以前记过的东西捞出来"。实际代码里，`AiCapability.SemanticSearch` 这个开关**只改了搜索框的 placeholder 文案**，过滤仍是：

```ts
ideas.filter((idea) => idea.content.toLowerCase().includes(k))
```

AI 调用一行都没写。这轮**先把文案说回实话**（"按关键词找"），真正的语义检索另立一条待办 —— 界面在承诺、代码不兑现，比不做更伤。

### 4.1 实施中冒出的一件事（原方案没预见到）

**可达性扫描扫出一个真洞**：`日程型 × 完全没排时间`（`kind = schedule` 且 `hasAnyTime === false`）
这条任务 — **四个列表同时不要它**：日历不要（没时间）、收集箱原口径不要（不是执行/习惯型）、
待办栏（已删）、项目列表只收挂进容器的。用户记了件事，然后就再也找不到它了。

原方案 §1.1 写的「`isTodo` 只看类型 —— 日程型不进」在这条上是错的，已改成：

```ts
// domain/todo.ts
export function isTodo(task: Pick<Task, 'kind' | 'time'>): boolean {
  if (task.kind === TaskKind.Execution || task.kind === TaskKind.Habit) return true;
  if (task.kind === TaskKind.Schedule) return !hasAnyTime(task.time); // ← 新增的例外
  return false;
}
```

配 1 条新测试（`日程型但没排时间 → 算`）+ 把原来那条"日程型不算"的用例改成显式带时间。

## 5. 风险

- **拖日历那条链路要重点回归**：面板 → 长按拿起 → 缩回把手 → 落到格子 → `buildTimeOnDay`。收集箱口径一变，它是首当其冲的。
- **分档的折叠状态不进库**：就是这一屏的 UI 状态，切页重进回"全展开"。这是有意的 —— 它不值得一个持久化字段。
- **「只呈现不改数据」意味着过期的永远不会自己变**。所以「已过期」档**必须排在五档最前**（`BUCKET_ORDER` 已经是），否则"呈现"等于没呈现。
- **首页不加"有 N 件过期"的行**（初稿倾向）：你只说了"重新出现在收集箱"，而首页现在已经有问候 / 下一节课 / 专注 / 习惯 / 反馈五块，再塞一行是替界面加东西。如果你要，一行的事。
- **日历页删掉第五栏后就只剩"有时间才进得去"的四栏**。这是可接受的（月历下拉清单已经在页内回答"这个月每天有什么"），但要记住：以后若想再把"欠着的"请回日历页，**落点就是那个磁吸面板**，不要再新开一栏。
- **5 栏变 4 栏会动到横滑分页**：`mode === 'todo'` 那三处"待办没有翻页箭头"的特判删掉后，四栏的翻页行为要一起回归一遍（月 / 周 / 日 / 课 各自的手势别被带坏）。

### 实施后回看（2026-10-10）

- 上面 6 条风险**只有第 1 条真的踩到了**（"收集箱口径一变，拖日历那条链路首当其冲"），

  `schedule × 无时间`）。教训：**改"谁能进列表"的判断时，要按"类型 × 有没有时间"的乘积
  把每个组合过一遍**，而不是只测改动点那几个用例。
- 第 2 条（折叠状态不进库）按原计划执行，没有代价。
- 第 6 条（四栏手势）跑全量测试 + tsc 后没发现问题，但**真机手势仍待验**（见交付清单）。
