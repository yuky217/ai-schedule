# 桌面小组件 —— 实施规划（待确认后再动手）

> 来源：用户反馈「没有找到小组件」。经核查，目前仓库里**只有设计文档 `docs/小组件设计-2026-10-08.md`，没有一行实现代码**，`react-native-android-widget` 也未安装。本文件是把设计落成代码前、先对齐的实施清单。

## 一、现状与结论

- ✅ 已有：`docs/小组件设计-2026-10-08.md`（限制分析、刷新策略、首批内容范围都写清楚了）。
- ❌ 缺失：`react-native-android-widget` 未进 `package.json`；无 Kotlin WidgetProvider、无 XML 布局、无 JS 数据拼装、无 `app.json` 配置。
- 所以手机上「找不到」是正常结果——它压根不存在。

## 二、首批范围（与设计文档一致，不做大）

**只读小组件**，桌面小卡显示两件事：

1. **今天** —— 今天的日程数量 / 下一个截止（一句话，如「今天 3 件事 · 下一个 14:00 交作业」）。
2. **下一节课** —— 距现在最近的这节课（课名 + 时间 / 地点）。

> 设计文档里定的「第一批只读＝今天/下一节课」就是这两块。交互上**只做「点一下打开 App」**，不做小组件内操作（后续第二批再做可勾选/可记一笔）。

## 三、技术选型（已定，无争议）

- **库**：`react-native-android-widget`（Android-only，MIT）。理由：官方 `expo-widgets` 目前 iOS-only，Android 只能走这个第三方库。
- **必须 development build**：库含原生代码，Expo Go 跑不了。现有 `run.sh apk`（assembleRelease）这条出包链要补一条 `widget-debug` / `widget-preview` 才能真机验。
- **华为 Mate 70 / 鸿蒙 4 兼容层**：APK 可装可跑（设计文档已记此前提），但**纯血 NEXT 一律作废**——升级前必须先导出备份 JSON。

## 四、要新建 / 改动的文件

| 文件 | 作用 |
|---|---|
| `package.json` | 加 `react-native-android-widget` 依赖 |
| `app.json` + `app.plugin.ts` | 注册 widget、声明 `receiver`、绑定配置插件（Expo config plugin 方式，与悬浮球模块同源） |
| `android/app/src/main/java/.../widget/MyWidget.kt` | Kotlin `AppWidgetProvider`：接收更新广播、用 `RemoteViews` 填文本、注册点击打开 App（`aischedule://` 深链） |
| `android/app/src/main/res/layout/widget_my.xml` | 小组件布局（标题行 + 今天行 + 下一节课行；RemoteViews 只支持固定一撮 View，无滚动/手势/动画） |
| `src/widget/index.tsx`（或 `src/widget/my-widget.tsx`） | JS 侧「数据拼装层」：从 `expo-sqlite` 读今天日程 + 下一节课，映射成 widget 需要的纯数据对象 |
| `src/widget/handler.ts` | `react-native-android-widget` 注册的 `WidgetTaskHandler`：被系统唤起时跑，把拼好的数据交给 Kotlin 层渲染 |
| `src/modules/widget-bridge.ts` + 原生桥 | App 内触发刷新：打开 App / 记完一笔 / 课表变动时，发广播让小组件立刻刷新（不等系统 30 分钟） |
| `docs/小组件设计-2026-10-08.md`（补） | 追加「已落地」章节，记录实际文件与刷新实测 |

## 五、两个必须提前定死的风险点

### 风险 1：小组件进程读不到我们的数据库

- 小组件由 launcher 进程绘制，刷新时唤起的是**一个没有界面的 App 进程**，有执行预算，且**不保证 `expo-sqlite` 已初始化**。
- **方案**：不在 widget handler 里现读库。改为 App 前台/数据变动时，把「今天 + 下一节课」算好写进一份轻量快照（`AsyncStorage` 或文件），widget handler 只读这份快照。这样 widget 进程零依赖我们的 DB，也最快。
- 代价：App 关掉后到下次系统刷新前，快照是最后一次算的（可接受，设计文档已说明这是小组件固有延迟）。

### 风险 2：刷新频率

- `updatePeriodMillis` 最小 30 分钟，Doze 下不可靠。
- **方案**：首批设 30 分钟兜底 + App 内主动广播刷新（覆盖「刚记了一笔、刚打开 App」这类即时场景）。暂不上 `WorkManager`（15 分钟档留给后续若真需要更频繁时再加）。

## 六、执行顺序（确认后按此走）

1. 装 `react-native-android-widget`，加 `app.json` 注册 + `app.plugin.ts` 配置插件。
2. 写 Kotlin `MyWidget.kt` + `widget_my.xml` 布局（先写死占位文本，确保能跑起来、能点开 App）。
3. 写 JS 数据拼装层（今天 / 下一节课口径复用 `domain/calendar-window`、`course.ts` 现有函数，不另造）。
4. 接快照读写 + 主动刷新广播桥。
5. 补一条能真机验的 build 命令（dev/preview），出包在真机确认：能加小组件、显示对、点一下进 App。
6. 更新设计文档「已落地」章节。
