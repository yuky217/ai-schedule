## 1. 解析器缺口（第一批，纯 domain，全部可单测）

按指令逐条对：

1. **时段词单独出现 → 默认时刻**。现在"晚上8点"认，但**只有"晚上"没有钟点**时不认。
   补映射：早上=7:00 · 上午=9:00 · 中午=12:00 · 下午=13:00 · 傍晚=17:00 · 晚上=20:00。
   ("晚上跑步" → 今天 20:00 跑步，过了就顺延)
2. **每2天 / 每2周**。`RepeatRule.interval` 字段早就存在（"间隔，1 = 每期都做"），解析器没产出它。
   补：「每2天」「每两小时」这类 `每N个单位` → `interval: N`。
3. **裸时刻的"最近有效"**（行为要拍板，见 §7-Q2）。现在是"过了就顺延到明天"；
   指令的例子（下午4点说"9点提醒我" → **今天21:00**）是**钟面就近**口径：
   在 {今天9:00, 今天21:00, 明天9:00} 里取**最近的未来**。两者差一层 +12h。
4. **每年3月6日**（与已拍决定冲突，见 §7-Q3）。现有决定是"每年"场景归**纪念日**
   （`marks.repeat_yearly`），`RepeatFreq` 刻意没有 yearly。

顺带：指令里"模糊日期一律解析成最近有效" —— 周X/周末已经是这个口径
（"最近的一个（含今天，过了就算下周）"），不用动。

## 2. 解析结果可见 —— 基本已有，补两处

- 时段词/重复/提醒的新口径解析出来后，**自动出现在现有 chip 上**（chip 的值本来就
  读 `parsed`），这条不用额外做。
- **高亮成小标签、点一下可改、符号标识**：输入框下那排 chip 就是这个交互
  （`🕒 今天 18:00` 点开改）。若想要"文本里那段词本身高亮"（输入框内富文本标记），
  RN 的 TextInput 做 inline 富文本很受限（嵌套 RN TextInput 不支持 styled spans），
  **投入产出比很低** —— 建议维持 chip 方案，把"识别到了什么"展示得更醒目一点
  （识别出时间时 chip 高亮 + 前缀图标）。要更好的效果只能换自定义编辑器，不建议。

## 3. 悬浮球 → 通知栏（第二批，原生）

**现状**：自绘小球浮在所有应用上（`OverlayService.kt`），2026-10-10 修过
MATCH_PARENT 全屏挡触摸的 bug。指令：**改成通知栏里一颗常驻通知，点一下弹快速记录，
不打断当前 App**。

**做法**（`modules/overlay/` 里改，不走 expo-notifications —— 要"点开就是输入"必须原生）：

1. 小球入口改成**一条 ongoing 通知**（`setOngoing(true)`，常驻通知栏；
   设置里的开关语义不变 —— "开/关"变成"发/撤这条通知"）。
2. 点通知 → 启动一个**透明 Dialog Activity**（`Theme.Translucent`），
   在当前 App 上面直接弹一个原生输入框 —— 当前应用不被切走，这就是"不打断"。
   系统悬浮窗权限（`SYSTEM_ALERT_WINDOW`）模块里已经拿到了，Android 10+ 的
   后台弹窗限制靠它豁免。
3. 提交 → 文本走 `aischedule://capture?text=...` 深链进主进程落库
   （唯一落库口 `quickCapture` 不动），Dialog 关掉，发一条静默的"已记下"通知作为回执。
4. **旧的小球代码先留着**（设置页两个开关并存一轮），真机验过通知栏方案再删
   —— 上一轮悬浮球刚炸过一次，没有回退方案的替换不划算。

**红线**：
- **语音**：指令说"打字或语音"。系统级语音识别（`SpeechRecognizer`）依赖 Google 服务，
  **Mate 70 Pro（鸿蒙）上没有**，鸿蒙自己的识别没有公开 SDK 通道。第一批只做打字，
  语音标记为"待真机调研"。
- 通知常驻会占用状态栏一格 —— 这正是"状态栏显示"想要的（见 §6）。

## 4. 通知增强（第三批，一半 expo 能做、一半原生）

| 指令条目 | 做法 | 可行性 |
|---|---|---|
| 通知按钮（完成 / 稍后提醒 / 暂缓 15分·1小时·3小时·明天） | expo-notifications 的 `setNotificationCategoryAsync` 支持给通知挂动作按钮，JS 侧收 response 事件处理"完成/顺延" | **第一批可做**；⚠️ App 被杀时按钮点击的处理要走原生 receiver 兜底，先做"App 活着时有效"，真机验证后再补 |
| 每日提醒 | 固定时刻（默认 8:00？）发一条"看看今天的安排"；内容是静态的（expo 排的是死内容），点开进首页 | 简单；**动态内容**（"今天有 3 件事"）需要原生每日 receiver，后补 |
| 按优先级设铃声 | Android 通知渠道（channel）自带声音设置；给"普通 / 重要 / 截止"三档各建一个渠道，设置页选声音 | expo 支持渠道 + 自定义声音文件；选系统铃声的 picker 要原生，先只给"默认/静音/随系统" |
| 提醒弹窗"总是显示" | 全屏 Intent（横幅式弹全屏）—— **expo 不支持**，要原生模块 | 原生工作量中等；鸿蒙对后台弹窗限制多，**真机行为要验** |
| 全局持续提醒（持续 5 分钟） | 到点后每 1 分钟重发一条 heads-up，共 5 条（expo 能做）；真"常驻 5 分钟"要 FSI 配合 | 降级方案可接受 |
| 覆盖勿扰 | `CATEGORY_ALARM` + 用户授予"勿扰访问"权限（系统设置里手动开） | **原生**；且鸿蒙对勿扰管控更严，给用户写清楚"这不是百分百" |

**建议顺序**：通知按钮 + 每日提醒先做（expo 层，风险小）；铃声渠道跟着；
FSI 弹窗 / 持续提醒 / 覆盖勿扰**单独一批**（原生 + 真机依赖重）。

## 5. 小组件（第四批）

现有：`react-native-android-widget` 快照机制，两个只读卡（今天 / 下一节课）。

指令要的增量：**日历+任务（周 / 月 / 时间轴）+ 习惯打卡**，要**实时预览**。

- 周视图卡：7 天列 + 当天任务点，快照量可控 —— 顺延第一批小组件的做法。
- 月视图卡：整月网格 + 圆点 —— 快照数据量仍可控（一个月的 dayShapes）。
- 时间轴卡：**不单独做** —— 它就是"今天"卡的加强版，把时间轴渲染进"今天"卡。
- 习惯打卡：**要能写**（点格子打卡）—— 这是第一批"只读"之后的第一个交互组件，
  `react-native-android-widget` 支持 tap 回调，但"点格子 → 落库 → 刷新快照"的链路
  要新搭（第一批只有"点开 App"）。
- **实时预览**：设置页/小组件管理页里渲染一张和真机组件同数据的预览卡。
  组件本来就是 RN 组件（`widgets.tsx`），预览 = 同一组件喂同一份快照数据，成本不高。

## 7. 拍板结果（2026-10-11 用户已定）

- **Q1 本轮做哪批** → **A：解析补齐**。通知栏入口 / 通知增强 / 小组件留待后续批次。
- **Q2 裸时刻"最近有效"** → **钟面就近**（16:00 说"9点" → 今天 21:00）。
  实施时补了一条它的边界：**重复任务不就近**（"每天8点吃药"早10点记 → 明天 8:00，
  带 repeat 的"8点"是"每天这个档"不是最近的钟面）。
- **Q3 「每年M月D日」** → **加 yearly**。`RepeatFreq.Yearly` 已加，四条链路全通：
  解析（每年M月D日 / 光杆每年）→ `repeat-next`（下一期 + 钳 2月29日）→
  `habit-period`（本期窗口 = 年块）→ 能力层 `understand`（freq 白名单）。
  重复预设选择器加「每年」（`REPEAT_PRESETS`，记录页与安排面板共用）。
- **Q4 "状态栏显示"** → 先跳过。
- **Q5 旧悬浮球** → 未及本轮（通知栏入口未做）。届时默认并存一轮看真机。
