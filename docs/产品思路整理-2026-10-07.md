# 产品思路整理（2026-10-07 凌晨）

> 性质：工作笔记，不是定论。产品定论仍以《项目主文档》为准。
> 背景：真机验证一轮下来，暴露的不是零散 bug，而是同一个主题——**"省事"这个第一目的，兑现得还太少**。

---

## 一、这个产品靠什么立足（不变的部分）

- **第一目的：① 省事（记录与规划不费力）；② 做完事（推动执行）。**
- 主流程：**记 → 分 → 落 → 行 → 完 → 回**。
- 设计原则：默认极简、按需展开；AI 是能力不是门面；本地优先 + 必须有备份出口。

这五条今晚一个都没动摇。动摇的是下面对它们的信任度。

## 二、现状盘点

### 已经是实的（验证过、有测试守着）

| 部分 | 状态 |
|---|---|
| 本体层五大件（收集箱 / 日历 / 项目 / 想法 / 首页） | 全建成，三视图日历、拖拽改期、甘特图都能用 |
| 主流程六环的落点 | 每一环都有页面承接（含「回」回顾页） |
| 数据层 | 本地库 + 备份导出/覆盖导入；262 条测试守着口径与不变量 |
| 专注闭环 | 专注 → 回执 → 打卡/滚期，口径已收成三个名字 |

### 虚的 / 断的（用户实际卡住的地方）

1. **入口层几乎不存在。** 主文档给入口层的定位是"轻、无感"，现在只有一个输入框 + 四个快捷按钮。AI 归类/拆解/排期默认全关——所以**「分」这一环完全靠手动**：记一件事 → 点进详情 → 点时间 → 选预设/滚轮 → 确认。每一步都对，合起来就是"懒得用"。
2. **提醒直到今晚才第一次被端到端看清。** 四个静默失败口（无时间/已过/权限/环境）攒了一个月，用户第一次真用时全撞上。
3. **整个 App 还住在 Expo Go 里。** 提醒、图标、"打开的是我的 App"的实感，都隔着一层壳；Expo Go 自身的噪音（红框、项目列表）也在消耗耐心。
4. **"省事"没有尺子。** 每次改交互靠感觉吵，没有裁判。

## 三、今晚沉淀为产品原则的东西

1. **同一交互修三层还没好 → 换一条不依赖它的路径。**（滚轮：滚动豪赌 → 点选保底）
2. **静默失败 = 用户以为成功。**（提醒、专注回执：关键动作必须有可见回执）
3. **每条数据在任何状态下都必须"找得到"。**（列表过滤互不覆盖 → 不变量测试守着）
4. **借成熟交互，不赌自写手势。**（能用系统语言就用系统语言）

## 四、三个决策点（按影响排序）

### 决策 1：先做 dev build，还是先打磨交互？

- **dev build**（把 App 装成独立应用）：提醒/通知/图标才变成真的，彻底摆脱 Expo Go 的壳与噪音。`app.json` 已预留 `SCHEDULE_EXACT_ALARM`。代价：折腾一次构建链。
- **先打磨交互**：继续在 Expo Go 里把"记 → 落"的成本砍下来。
- 我的倾向：**dev build 先行**。理由：提醒是"做完事"的一半，Expo Go 里它永远半真半假；且用户对 Expo Go 已经没耐心。打磨可以照常并行。

### 决策 2：AI 能力层的第一刀切在哪？

「分」全手动是"省事"没兑现的最大单一原因。如果开，第一刀建议：

> **一句话自动判「灵感还是任务」**——输入框敲完，先按内容给出去向建议（想法库 / 收集箱），用户确认或改。范围最小、不碰排期、直接兑现主文档 5.1 的两档分流。

不开也成立（本体层本就独立可用），但要明确"暂时不做"而不是"忘了做"。

### 决策 3：给「省事」定一把尺子

建议定一条硬指标并写进主文档：

> **记一件事到它安放好（有了时间或进了对的桶），默认路径 ≤ 2 次点按。**

现状对照：手动路径是 4~6 次点按。这条尺子会逼着每个交互改动回答"省了几下"，也是将来 AI 入口的验收标准。

## 五、下一步建议（最小集合）

1. 定 dev build 的构建方式（EAS build 或本地 `expo run:android`），做一次。
2. 用决策 3 的尺子把「记 → 落」路径重新走一遍，砍点按数。
3. 决策 2 拍板：AI 第一刀开或明确缓做。
4. 真机四项验证收尾（提醒链路已可见化，剩专注页滑动、收集箱撤销、滚轮点选）。
