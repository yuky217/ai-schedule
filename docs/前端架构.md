## 一、分层总图

```
┌──────────────────────────────────────────────────┐
│  app/          路由页面（expo-router 文件即路由） │
│    (tabs)/     5 个 Tab：首页·收集箱·日历·项目·想法 │
│    其余        全屏页：详情/专注/课表/设置/记录…    │
├──────────────────────────────────────────────────┤
│  components/   界面件（不含业务判断）              │
│    *_sheet     底部弹层（时间/清单/单选/调课…）     │
│    task-row 等 列表行、日历块 —— 只渲染不决策       │
├──────────────────────────────────────────────────┤
│  state/        zustand 仓库                        │
│    app-store   全部业务数据 + 动作（唯一写入口）     │
│    settings-store  用户偏好（默认时长/AI 配置…）    │
├──────────────────────────────────────────────────┤
│  domain/       纯函数：所有口径与判断规则           │
│  entry/        入口能力：记录、通知、悬浮球、抓课表  │
│  capabilities/ AI 能力层（OpenAI 兼容协议）         │
├──────────────────────────────────────────────────┤
│  data/         SQLite 读写（repositories 收口）     │
└──────────────────────────────────────────────────┘
```

**三层铁律**：界面不碰 DB；联动一律走 `app-store.refresh()`；
"偶尔看一眼"的读用 `dataVersion` 当失效信号（不订阅整库）。

## 二、数据怎么流（以"记一件事"为例）

```
输入框(capture-input) ──onSubmit(text, options)──▶ 页面
   │ options 里带：手动时间/清单/重复/提醒/AI解析结果
   ▼
quick-capture.ts（唯一落库函数）
   ├─ 解析：input.parsed（AI）?? parseSchedule（本地正则）
   ├─ 分流：decideRoute → 想法库 / 收集箱 / 日历
   ├─ 提醒：resolveReminderMinutes（手动 > 文字 > 类型默认 > 不提醒）
   └─ 排通知：scheduleTaskReminder（按 reminderFireTimes 展开重复期）
   ▼
taskRepository / ideaRepository（data 层，mappers 是唯一读写库口径）
   ▼
app-store.refresh() → dataVersion+1 → 各页自查要不要重读
```

改动口诀：**口径改 domain，动作进 store，界面只接线**。

## 三、导航结构

- **5 Tab**：首页 / 收集箱 / 日历 / 项目 / 想法；
- 习惯、纪念日、课表是**二级页**（不占 Tab）；
- 首页入口「＋」→ `/capture`（记录页，含时间预设）；
- 专注页 `/focus`：进入即计时，退出兜底落库，结束才判完成；
- 详情页定式：标题备注 → 时间 → 子任务 → 「更多设置」折叠 → 常驻底栏。

## 四、主题与视觉

- **令牌**（`constants/theme.ts`）：暖灰中性面 + 近黑近白两套；**无彩色强调**——
  界面上唯一的"重色"是文字本身（主按钮 = 文字色填充）；
- 对比度全部实测 ≥ 4.5:1，改色要算不能凭感觉；
- 间距走 `Spacing` 刻度（2/4/8/16/24/32/64），不出现刻度外的魔法数；
- 字体：计时器用 `tabular-nums`（数字跳动不移位）；
- `MaxContentWidth = 800`：平板/Web 上内容不摊大饼。

## 五、改一个功能的触点清单

| 想改… | 要动 |
|---|---|
| 识别规则（时间/地点/标题…） | `domain/parse-schedule.ts` + 同名测试 |
| 提醒行为 | `domain/reminder.ts`（口径）+ `entry/notifications.ts`（排程） |
| 列表里一行长什么样 | `components/task-row.tsx` |
| 详情页多一个设置 | `app/task/[id].tsx` + 对应 sheet 组件 |
| 新增页面 | `app/` 下建文件 → 先跑 tsc，只有 TS2345 才 `expo start` 生成 typed routes |
| 数据库结构 | `data/db/schema.ts` 迁移 + `mappers.ts` + 备份七处（见 README） |

## 六、测试网

- **domain 纯口径**：单测密集（识别、分流、提醒、排序…）；
- **repositories**：vi.mock 掉 db client；
- **守卫测试**：扫源码防回潮（锚点判据、`#清单 @标签` 关键词…）；
- 纪律：**测完验牙**——把新逻辑改回旧写法，测试必须变红，否则测试没咬合。
