# 判断规则说明书

> 你记一件事的时候，系统替你做了一堆判断。这份文档把它们全部摊开：
> **每条规则的现状是什么、为什么这么定、改它要动哪里**。
> 定论以本文档为准，改动请同步更新（文档和代码一起走，否则它就开始骗人）。
>
> 最后更新：2026-10-08

---

## 〇、一条记录的一生（总览）

```
你输入一段话（或粘一段通知）
        │
        ▼
   ┌─ 解析 ─┐   AI 理解（配了才走）──校验不过──┐
   │ 标题提炼 │                                │ 失败/没配，静默退回
   │ 时间     │◄───────────────────────────────┘
   │ 地点     │
   │ 重复     │
   │ 提醒     │
   └────┬────┘
        ▼
   分流：想法库 / 收集箱 / 日历
        │
        ▼
   落库 + 排提醒通知
```

两条铁律贯穿所有规则：

1. **手动的永远压过猜的。** 你点过、选过、填过的，系统不再自作主张。
2. **识别不出就老实承认。** 宁可少识别一项，也不猜一个错的——错的时间比没有时间糟得多。

## 一、解析：一段话拆出五样东西

### 1. 标题（`pickTitle`）

粘一整段通知时，标题 = **第一个像名字的非空行**：

- 跳过寒暄（"各位…你们好"）、分节小标题（"活动时间及地点："）；
- 剥掉「关于…的通知」的壳，取里面的正文；
- 超过 40 字截断，**截掉的部分一个字不丢，全部进备注**；
- 万一切完什么都不剩（"明天9点提醒我"），退一步只切时间——空标题比丑标题糟。

### 2. 时间

- 认「10月14日 19:00-21:50」「下周三下午三点」「明天9点」这类写法；
- 有起止 → 固定型（日历上是一块）；只给一个点 +「前/截止」→ 截止型；
- **识别不出时间 = 没有时间**，不会猜。

### 3. 地点

**只认标签写法**：「地点：」「地址：」「场地：」「位置：」+ 内容。

- 不认"在体育馆开球"这种句子里的地点——猜错的代价（把"在"字后面的东西当地址）大于漏掉的代价；
- 值遇到句读或"请/注意/务必/记得/联系"就停，不吃掉后面的整句话；
- 和时间冲突时**时间赢**：如果"地点"标签抓到的其实是时间（跨行误判），整个地点作废。

### 4. 重复

认「每天/每周/每月/隔天/每周3次」等写法。识别出重复但只算不写 = 明天不再出现，所以一定写进任务。

### 5. 提醒

**动词是入场券**：只有出现「提醒/叫我/喊我/通知我/别让我忘」这类词，才算你提了提醒。

- "提前半小时提醒我" → 提前 30 分钟；
- "记得提醒我"（没给量）→ 按类型给默认值（见第三节）；
- 一个字没提 → **不提醒**。

## 二、分流：这件事去哪儿

| 条件 | 去处 | 类型 |
|---|---|---|
| 你标了「灵感」 | 想法库 | idea |
| 有起止时间（固定型） | 日历 | schedule |
| 有截止时间 | 日历 | execution |
| 没有任何时间 | **收集箱** | 兜底分类（见下） |

收集箱的兜底分类（没有时间信息时才用）：

- 写着「每周/每天/隔天/习惯」或具体习惯词（跑步、背单词…）→ 习惯；
- 写着「灵感/想法/也许/考虑」→ 灵感；
- 其余 → 普通待办。

## 三、提醒：最复杂的一块，慢慢说

### 1. 三种状态

`reminderMinutesBefore`：

| 值 | 含义 |
|---|---|
| `null`（默认） | **不提醒**。没提就是不打扰 |
| `0` | 准点响 |
| `> 0` | 提前 N 分钟响 |

### 2. 谁说了算（优先级从高到低）

1. **你当场点的**（chip 里选过，包括选了「不提醒」）；
2. **文字里写明的量**（"提前半小时"）;
3. **只提了提醒没给量** → 按类型给默认值；
4. 其余 → 不提醒。

chip 上显示的值和库里存的值**必须同源**（都走 `resolveReminderMinutes` 一个函数），不会出现"界面写 10 分钟、库里存不提醒"。

### 3. 类型默认值（现状）

| 事情的类型 | 默认 | 理由 |
|---|---|---|
| 截止型（"12:00 前交请假条"） | **提前 1 小时** | 截止要留出"把它做完"的时间，准点提醒 = 通知你已经晚了 |
| 重复 / 习惯（"每天 8 点吃药"） | **准点** | 到点就该做，提前 10 分钟没有价值 |
| 其余（开会、活动、约好的事） | **提前 10 分钟** | 你需要的是"该动身了" |

### 4. ⚠️ 待拍板：有起止时间的要不要再分（见本文档末尾「待定方案」）

### 5. 什么时候真的会响

- 已完成 → 永不响；
- 没时间 / 时间已过 → 不响（昨天的会不补提醒）；
- 提前量时刻已过但准点没到 → **退回准点响**（响得晚比不响好）；
- **重复任务一次排未来 7 天的每一期**，且至少带上最近一期——"每月 25 号"的下一期哪怕在 7 天外也要有，否则这条任务一条提醒都不会有；
- 每次启动补满 7 天窗口（安卓一次性通知有数量上限，一次排太多会被系统静默丢掉一部分）。

### 6. 通知上写什么

标题 = 任务名；正文 = 「还有 40 分钟开始 · 学生活动中心」——**地点跟着提醒一起送达**，不用点开详情就知道往哪走。

## 四、排序

- **收集箱**：你手动拖的顺序（`sortOrder`），新记录排在最后；
- **日历同一天内**：按时间先后；时间相同的按标题排序（保证列表稳定，不会每次打开顺序乱跳）；
- **课表**：按开始时间，同名课程按拼音；
- 所有排序都有**固定次关键字**（id / 标题），杜绝"同一份数据两次排序结果不一样"。

---

## 五、状态

- **完成只由明确勾选触发**：点行/块 = 进详情，不会顺手把事标记完成；
- **子任务全部完成 → 父任务自动完成**；反过来父任务重新打开，子任务不跟着动；
- **打卡不改状态**（习惯是频率，不是一次性的"做完"）——唯一例外：**频率型习惯**（"每周 3 次"）当周打满即完成；
- 删除是软删除，可恢复。

---

## 六、AI 与本地的分工

- 配了 AI（设置页）→ 先让模型读，它认得出本地正则认不出的说法（"例会改到周五了"、"没有具体日期的下周三"）；
- **AI 只是加分项**：没配、网络不通、答得不成形 → 拿到 null，静默走本地识别，**AI 挂了不能让"记一件事"挂掉**；
- 模型给的时间不成形（缺锚点、格式怪）→ **整体作废**退回本地，不会拿半残的时间落库；
- 两条路产出的结构完全同构，分流、提醒默认值这些规则**一份代码两个来源共用**——谁来解析只影响"谁更懂这段话"，不影响落库口径。

## 七、待定方案（等你拍板）

### 有起止时间的日程，提醒默认量要不要按"在哪儿"分？

**现状**：一律提前 10 分钟。

**提议**：按**有没有地点**分两档——

| 判断（系统自动，不用你填） | 默认 | 理由 |
|---|---|---|
| 有地点的日程（地点是你填过的、或通知里带「地点：xxx」识别到的） | **提前 20 分钟** | 要动身：走路、换教室、找楼，10 分钟只够你从座位上站起来 |
| 没有地点的日程（线上、或你自己安排的时段） | 保持 **提前 10 分钟** | 只需要"准备开始了"，不需要在路上 |

**为什么用地点当判断依据**：它是结构化数据（已填/已识别），判断零成本、零误判。相比之下"开会 vs 自习"要靠猜关键词——猜错的提醒比不给默认值更烦。

**不做的**：按时长分（长活动提前更多）、按周期分（每周例会提前更少）——都靠猜，先不引入。
