## 0. 总纲

把"两个收集箱"合并成**一个底部磁吸浮层**；收集箱内的"待规划"标签、"这是灵感"按钮、分行拆子任务都去掉；任务详情页把"完成"说清楚、更多设置不再藏；时间加"全天"；日历范围放宽。

## 1. 日历范围放大（已确认：页面占比）

**现状**：`calendar-window.ts` 月视图固定 `6×7` 网格，两端各 `pad 7` 天；五栏（月/周/日/课/待办）各自取窗口。日历周围留白偏多，月格在屏上占比偏小。

**已确认方向（2026-10-10）**：说的"范围放大"是**页面占比**——日历要在屏幕上占更大一块，减少外围留白、把月格放大、信息更舒展。**不动时间跨度、不加新视图、不改导航范围**。

**改动（纯布局/样式）**：
- `Screen` 顶部栏、各栏 header 的纵向 padding 收紧；
- 月格行高/字号/圆点尺寸上调，让 6 行铺满更多屏高；
- 周/日/课视图同理让时间轴更粗、留白更少。
- 不触碰 `calendarWindow` 的取数范围（数据窗口不变，只动渲染占比）。

## 2. 收集箱统一面板（核心改动）

### 现状与问题
- **月视图底部 `bottomBar` 块**（`calendar.tsx:948`）：常驻占一整块竖向空间、不可收起；是拖拽到日期格的唯一源头（仅月视图）。
- **右侧 `SideDrawer`**（`side-drawer.tsx`）：从右拉出，但它是 `position:absolute` 全屏层，**盖住月历** → 拉出后无法把任务拖到日历格上。
- 两个都列同一份 `inbox`，用户感觉"两个折叠收集箱"重复（你之前也定性过）。

### 方案：一个底部磁吸浮层 `InboxPanel`
用**磁吸点（snap points）**的浮层取代"底部栏 + 右侧抽屉"两套：

1. **peek（收起）**：仅一条细条 `收集箱 · N 件`，**不占竖向方块**；点一下 / 上拉手势展开。
2. **expanded（展开）**：列出 inbox 行（可拖拽）。**拖某行时面板自动缩回 peek**，露出上方月历格 → 直接解决"拉出后无法拖到日历"。
3. **full（拉到底）**：继续上拉超过阈值 → 跳 `/inbox` 全页（"拉出后再拉可以拉到收集箱界面"）。

**"悬停显示事项名称 / 事件栏随之改变形态"** 落到形态切换上：
- peek 态：行折叠成胶囊，只显标题（或"N 件"）；
- expanded 态：展开成完整行（标题 + 拖拽抓手 + 勾选）。

**拖拽机制**：复用现有 `useCrossDayDrag`（`registerCell` 命中月历格、`ghostStyle` 浮层覆盖日历），把 `DraggableTaskRow` 放进 `InboxPanel`。任何视图都能拉出（替代右侧抽屉的"随时瞥一眼"），且月视图里它就是拖拽源（替代底部栏）。

**去掉**：`SideDrawer`（被取代）、月视图 `bottomBar`（被取代）。

**磁吸实现**：`reanimated` 的 snap 点 + `Gesture.Pan`，按位移/速度判定落到哪一档（参考现有 month-plan 的跟手逻辑）。

### 已确认（2026-10-10 用户拍板）
> "两个收集箱分工是一样的，它们就是同一个。"

不再讨论分工——直接**统一为一个浮层**，删除"底部栏 + 右侧抽屉"两套。两处渲染合并进 `InboxPanel`，数据仍只有一份 `inbox`。

## 3. 收集箱内的细节

### 3.1 事件时间新增"全天"
- `TaskTime`（`domain/task.ts:26`）加 `allDay?: boolean`；`date-time-picker.tsx` 在"日程 / 截止"两档旁加第三档 **「全天」**，选中后隐藏时刻滚轮、只留日期。
- 显示层随之区分：月历形状（全天=横幅而非定时块）、今日计数（"下一个截止"只显日期）、widget 快照（`describeDraft` 之类）。
- 涉及：`domain/task`、`domain/enums`、`mappers`（落库列）、`calendar shape`、`widget/snapshot`。
- `normalizeTaskTime` 要让"全天"仍有一个锚点（当天 00:00）以便被日历窗口收进。

### 3.2 收集箱新建不要"这是灵感"按钮
- `capture-input.tsx:312` 的 `showIdeaToggle` 在收集箱入口（`/capture` 带 `from=inbox`）传 `false`。
- 自动分流仍由 `domain/routing.ts` 的 `decideRoute` 负责（文本里含"灵感/想法"会进想法库），所以手动勾选是冗余的。

### 3.3 长按拖拽有时不成功（修复）
- **根因**：`use-cross-day-drag.ts:209` 用 `Gesture.Pan().activateAfterLongPress(200)` 包在 `TaskRow`(Pressable) 外层，`Pressable` 的触摸与 RNGH 抢手势；200ms 偏短，手指长按期间微动即取消长按 → 偶发拖不起来。
- **方案**：把"点开 / 勾选 / 长按拖"收进**同一套 RNGH 组合手势**（`Gesture.Tap` + `Gesture.Race(LongPress, Pan)`），不再依赖内层 `Pressable` 的 `onPress`；长按阈值提到 ~350ms；保留 `shouldCancelWhenOutside(false)`。
- 同步复核收集箱页 `ReorderableList` 的长按（同样偶发失效要一并修）。

### 3.4 收集箱页任务不每条显示"待规划"
- `task-row.tsx:118` 对任意无时间任务都渲染 `待规划`，收集箱页每条都中招、冗余（收集箱本身就是待规划桶）。
- `TaskRow` 加 `showPendingLabel?: boolean`（默认 `true`），收集箱页传 `false`。

## 4. 子任务：去掉"分行 = 多条"

- **现状**：`task/[id].tsx:225`、`container/[id].tsx:115` 用 `splitSubtaskLines` 把多行文本炸成多条子任务。
- **改动**：
  - 去掉分行拆分——输入框**整段作为一条**子任务；回车 / 「加」= 建一条。
  - **连续创建（2026-10-10 确认）**：提交一条后输入框**自动清空并保持聚焦**，可一条接一条地快速录入（类似 Things / Todoist 的 quick-add 循环），不打断心流；不用反复点输入框。
  - placeholder 改为「加一个子任务」。
  - 删除 `splitSubtaskLines` 的调用（文件如无人再引用可删）。
- **与积木式归档一致**：子任务是用户一条条主动放的离散块，不是一段文本自动炸开。

## 6. 滴答清单积木式归档（参考结论）

- **Arrange Tasks**：日历页把未排期任务长按拖到日期 = 我们的收集箱拖到日历 ✓ 思路一致。
- **清单 / 文件夹拖拽归档** = 我们的 `container`（目标 / 项目）。
- **子任务清单** = 我们的 `subtasks`（积木块）。

### §3.3 的真实根因（与原方案不同，已修正）
原方案写的是「`Pan.activateAfterLongPress` 阈值偏短」。实际查证 RNGH 类型定义：
**`Pan` 根本没有 `maxDistance`**，只有 `LongPress` 有。所以只要按住期间手指抖动
超过触摸阈值，长按就前功尽弃 —— 抬阈值只是把窗口拉长，治不了根。

改法：`Gesture.Simultaneous(LongPress(minDuration=300, maxDistance=24), Pan(manualActivation))`。
- 长按只负责「拿起」，**容忍 24pt 抖动**；
- Pan **手动激活**：`pickedUp` 为 1 之后手指一动才转拖拽（没拿起就不跟页面滚动抢）；
- **点击仍归行内那个 `Pressable`**，所以「点开详情 / 勾完成」零回归
  —— 也避免了原方案「改成 Gesture.Tap 后点勾选圈会顺手打开详情」的坑。

### §3.1 的显示层（四处，不只是选择器）
- 行（`TaskRow`）与详情页时间文案：显示「全天」而不是假的 `00:00`；
- **日视图给全天单独一栏「全天」横幅，不进时间轴** ——
  时间轴从 `START_HOUR=5` 开始，全天的 00:00 会落到**负坐标**上（画在可视区外），
  看着就像"这天没这件事"；
- **小组件「下一个截止」**：⭐ 全天要拿 `endAt`（当天 23:59:59）去比，
  用 `startAt`（00:00）比**永远比不过现在**，一条"今天全天"的事会凭空从卡片上消失。
  口径收在新的 `domain/task.pendingUntil`，带 4 条测试（已验牙）。
